# 商务礼仪训练包 v1

## Goal

在现有销售训练项目中完整实现“商务礼仪训练包 v1”，把新人训练路径里的商务技巧模块从“文章 + 考试 + AI 教练入口”升级为“资料可版本化、能力点可达标、AI 产物可审核、训练记录可追溯、管理端可看卡点”的闭环训练包。

本任务严格以以下文档为权威需求来源：

* `docs/plans/2026-06-14-business-etiquette-training-pack-prd.md`
* `docs/plans/2026-06-14-business-etiquette-training-pack-implementation.md`
* 源资料：`docs/lujingshuji/商务礼仪-新人的第一本职业素养手册-完整版.md`

## Requirements

按实施计划 Slice 1-11 顺序交付，每个 Slice 都必须形成可独立验证的端到端能力，不做只落后端或只落前端的悬空实现。

1. **资料导入与版本草稿**：管理员可将商务礼仪 Markdown 导入为训练包草稿版本；保留原始 8 节、H2 微章节、H3 知识点；导入不影响学员端，发布前可预览；写入操作日志。
2. **7 个训练小单元与阅读路径**：学员端商务礼仪首屏展示 7 个训练小单元；小单元详情展示覆盖章节、能力点、阅读进度和下一步 CTA；后台配置开放、跳过、阻断和章节绑定规则。
3. **能力点模型与版本快照**：第一版能力点归属于商务礼仪训练包版本快照；管理员可管理 8 个主能力点；发布训练包时冻结能力点快照，题目、小测、AI 教练、训练记录、卡点视图都引用该快照；第一版不新增独立全局能力点目录。
4. **AI 出题草稿箱**：AI 可从章节生成单选、多选、简答题草稿；草稿必须进入审核箱，不得自动进入正式题库；通过后才绑定章节/小单元/能力点并对学员可见；草稿保留来源、prompt 版本、模型配置、审核记录和修改 diff。
5. **小单元测验与能力点掌握度**：小测只使用已发布题目；题目必须绑定能力点才能作为达标依据；提交后计算能力点分数、掌握等级、薄弱点和建议回看章节；记录冻结资料、题目和能力点版本。
6. **AI 教练 prompt 与 typed 训练卡契约**：AI 出题、训练卡生成、评分反馈和补救建议全部复用现有 `PromptTemplateService` / prompt 模板治理链路；定义 ABD typed 训练卡和反馈 schema；缺少已发布 prompt、schema 非法或 contract hash 不一致时 fail closed。
7. **AI 教练训练工作台**：把当前聊天页升级为训练卡优先的工作台；支持场景判断卡、改写卡、角色回应卡；自由追问不得绕过训练卡状态机；桌面和移动端布局可用。
8. **AI 教练达标与补救流**：AI 教练训练结果写入能力点得分和掌握等级；根据配置判断小单元是否达标、是否阻断、是否进入待人工复盘；未达标时推荐章节和重练卡片。
9. **资料新版发布影响分析与重练策略**：发布前展示章节、小单元、题目、能力点、prompt/卡片配置和在学人员影响；支持仅新学员、自愿切换、指定人群重练；老学员切换或重练必须创建新的 training attempt/session，不覆盖旧记录。
10. **管理端卡点视图**：管理者可按学员、小单元、能力点、状态筛选卡点；展示最近回答、教练反馈、能力点分数、掌握等级、建议回看章节、建议重练卡片和带教干预建议；人工复盘写审计日志。
11. **种子数据与端到端验收**：提供可演示 seed，能创建商务礼仪训练包、7 个小单元、8 个能力点、示例题目草稿/已审核题目、示例 AI 教练 prompt；覆盖一条学员学习闭环和一条管理端复盘闭环。

## Non-Negotiable Constraints

* PPT 演讲模块保持现状，不改录音评分路径。
* 不实现实时 WebSocket 客户对练。
* 不把 CopilotKit 作为训练工作台核心渲染层。
* AI 只生成草稿，不得自动发布题目或 prompt。
* AI 教练不得渲染任意 JSX/HTML，只能输出后端白名单 typed UI events。
* 能力点第一版归属于训练包版本快照，不新增独立全局能力点目录。
* AI 出题、训练卡生成、评分反馈和补救建议必须复用现有 `PromptTemplateService` / prompt 模板治理链路。
* 自愿切换新版和指定重练新版必须创建新的 training attempt/session；历史训练记录保留旧版本快照，不被新版结果覆盖。
* 题目、能力点、通过线、开放规则、补救策略、文案、权限和版本策略不得硬编码在页面组件或零散函数中，必须走后端配置、模板、权限和审计体系。

## Technical Approach

* 先加载 `trellis-before-dev`，读取后端、前端、跨层和配置化规范，再写代码。
* 后端优先复用 `sales_trainer` 现有材料、题库、路径、AI Coach、操作日志、权限投影和 prompt 模板治理能力。
* 前端继续通过集中 API facade/types 消费后端，不在页面组件直接拼业务 API。
* 每个 Slice 先补契约、类型、服务测试，再实现后端、前端、权限、配置、审计和 fail-closed 行为。
* 涉及可调整业务规则时，必须有默认值、读取位置、管理入口、权限、校验、兜底和审计；当前迭代不实现的后台页面，也要预留配置读取和校验层。

## Acceptance Criteria

* [ ] 管理员可以导入 `docs/lujingshuji/商务礼仪-新人的第一本职业素养手册-完整版.md` 生成训练包草稿，预览后发布。
* [ ] 学员端商务礼仪模块展示 7 个训练小单元，而不是直接展示 8 节书目录。
* [ ] 小单元详情页展示原文章节、阅读进度、能力点、小测入口、AI 教练入口和未达标补救建议。
* [ ] 后台可管理并发布 8 个能力点；发布后形成训练包版本快照，历史记录不被后续编辑改写。
* [ ] AI 出题草稿箱支持生成、筛选、编辑、拒绝、通过；未审核题目不可进入学员端、小测、AI 教练题源或达标计算。
* [ ] 小单元测验使用已发布题目并基于能力点计算掌握等级。
* [ ] AI 教练只接受/输出白名单 typed ABD 卡和结构化反馈，所有 prompt 运行时记录版本和 contract hash。
* [ ] AI 教练工作台以当前训练卡为主视觉，支持提交、反馈、追问、结束面板和移动/桌面布局。
* [ ] 未达标时推荐回看章节和重练卡片；超过配置阈值后进入待人工复盘。
* [ ] 资料新版发布前有影响分析；老学员自愿切换或指定重练会创建新 attempt/session，旧记录继续引用旧版本。
* [ ] 管理端卡点视图能展示能力点、证据、干预建议和人工复盘状态。
* [ ] 所有发布、审核、回滚、重练指派、人工复盘、AI 失败和配置非法场景有明确错误或审计日志。

## Verification

每个 Slice 完成后运行最小相关检查；最终至少运行：

```bash
cd backend
pytest tests/unit/test_newcomer_training_path_*.py tests/integration/test_newcomer_training_path_*.py

cd web
npx vitest run src/app/\(dashboard\)/sales-trainer src/app/admin/sales-trainer src/components/admin/sales-trainer src/components/sales-trainer src/lib/sales-trainer
npx tsc --noEmit
```

按实际改动补跑相关检查：

* 后端：`sales_trainer` 服务/API/权限/审计日志测试、`prompt_templates` contract tests、API contract tests、必要的 migration checks。
* 前端：学员端商务礼仪页面、AI Coach 工作台、管理端资料/题库/能力点/prompt/卡点视图测试。
* 浏览器 QA：至少证明管理员导入发布、学员完成一个小单元、管理端查看卡点三条路径。

## Out of Scope

* 不重构 PPT 演讲模块或音频评分体系。
* 不做全公司通用知识库导入系统。
* 不做复杂多人审批流，第一版使用管理员审核发布。
* 不做生产部署、外部账号授权、付费模型凭证接入或真实用户数据操作。
* 不改默认分支历史、不提交无关架构优化、不顺手重构无关模块。

## Pause Conditions

暂停并向用户报告的情况：

* 需要生产数据、真实付费模型凭证、外部账号授权或公开部署。
* 需要破坏性数据库操作或不可回滚迁移。
* 需要全公司通用能力点目录、复杂多人审批流、权限边界或生产 prompt 最终文案的产品裁决。
* 题目质量必须人工验收后才能继续。
* 同一阻塞连续 3 轮无法通过本地证据推进。
