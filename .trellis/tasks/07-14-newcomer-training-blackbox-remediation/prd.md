# 修复新人训练黑盒回归缺陷（域名除外）

## Goal

在不等待正式域名和 HTTPS 配置的前提下，修复 2026-07-14 黑盒报告中可由应用代码解决的新人训练缺陷，恢复登录、活动加载、提交、解锁、审核和后台管理主流程，并补齐错误态、用户语言、响应式与回归测试。

## What I already know

- 用户明确要求先修复“域名之外”的问题；正式域名、证书、HTTP 强制跳转与真实安全上下文媒体回归暂不在本任务内。
- 黑盒报告包含 QA-001 至 QA-012：P1 重点为 UUID 兼容、首活动加载、服务端解锁、达标审核崩溃、开发登录超时；P2/P3 包含刷新恢复、后台新建、日志语义、性能、运行时配置、内部术语和移动布局。
- 工作区已有大量未提交修改，且部分与新人训练重叠；必须保留并基于现状增量修改，不覆盖未知改动。
- 仓库存在 `.codegraph/`，理解共享链路和影响面必须优先使用 CodeGraph。

## Assumptions

- “先修复其他的”授权处理所有无需域名即可完成的代码缺陷，而不是只修一个 P1。
- QA-001 中 UUID 能力检测/兼容生成器属于本任务；全站 HTTPS、浏览器麦克风安全上下文与生产 WebSocket TLS 由后续域名任务处理。
- 优先保证正确性与关键路径稳定，再在同一任务内处理可安全验证的性能和文案问题；无法在本地证明的部署项会明确列为未验证。

## Requirements

- 统一替换直接依赖 `crypto.randomUUID()` 的客户端关键链路，使用安全上下文兼容且碰撞风险可接受的客户端 ID 生成入口；重复提交仍需幂等保护。
- 修复开发者快速登录的请求取消/超时竞态，重复点击只建立一个有效会话，并提供可定位的失败信息。
- 修复学员活动首次进入、刷新和返回时长期 loading/空白的问题，提供明确的超时、错误与重试状态。
- 由后端权威计算并执行活动前置与锁定状态；活动详情深链不得绕过必修顺序，前端展示用户可理解的锁定原因。
- 修复达标审核对缺失状态桶/未知状态的未定义访问，覆盖空数据、部分状态与失败重试。
- 修复管理端学习内容新建入口与路径添加操作的导航/状态竞态，维持当前页面内完成的交互。
- 改善操作日志 ViewModel：默认展示业务动作、操作者显示名、对象名称、结果与原因；UUID、原始数据和内部枚举仅保留在受控技术详情。
- 补齐实时对练运行时配置与录音活动达标信息的契约和展示，后台发布版本与学员运行时可追溯。
- 清理普通管理界面的 seed/Smoke/Phase/E2E、UUID、原始内部枚举等工程信息，保留必要的管理员调试入口。
- 修复 320–430px 管理端主操作换行问题。
- 对可定位的慢查询/重复请求/首屏阻塞做最小性能修复；慢网超过 1 秒时提供明确加载说明。

## Acceptance Criteria

- [ ] 在没有 `crypto.randomUUID` 的浏览器环境中，考试、上传录音、AI 教练和实时对练可发起唯一业务请求，不再显示原始 TypeError。
- [ ] 开发登录在正常、慢请求、重复点击、401/500 场景行为确定；正常请求不被错误 abort。
- [ ] `ppt-intro-audio` 及代表性活动冷加载、刷新、返回多次均在有限时间内展示内容或明确错误/重试状态，不出现无限 loading/空白。
- [ ] 未完成首任务时，后续必修活动 journey 状态为 locked，直接请求活动详情也不能启动；完成、失败重试、选修、待审核和已完成状态符合规则。
- [ ] 达标审核在空数据、缺状态桶、未知枚举、部分数据、接口失败时不崩溃。
- [ ] 管理学习内容新建和路径内添加可重复稳定打开；提交/加载状态可见且防重复。
- [ ] 普通业务界面不直接显示 seed、Smoke、Phase、E2E、UUID、原始枚举或 raw JSON。
- [ ] 学员端能看到实时对练角色/场景/目标/评分规则，以及录音通过分和正式示例状态；数据来自发布版本快照。
- [ ] 320/375/390/430/1400px 关键页面无横向溢出，主操作文字不被逐字拆行，键盘焦点和 accessible name 保持可用。
- [ ] 相关单元/集成/契约/E2E 回归通过，前后端 lint、类型检查及受影响测试通过；无法执行的外部 Provider/HTTPS 回归有残余风险说明。

## Definition of Done

- 自动化测试覆盖每个已修根因及关键失败边界。
- 前后端 lint、类型检查和受影响测试通过。
- 影响分析覆盖共享 UUID、journey/readiness/API DTO 与管理组件调用者。
- 无新增非必要依赖、无无关重构、无覆盖用户现有未提交改动。
- 发布和回滚路径明确；域名/HTTPS/真实 Provider 项显式留待后续。

## Technical Approach

- 先建立可重复测试反馈环，再按 P1→P2→P3 修复。
- 共享能力放入已有 API/ID/状态映射层，不在页面中重复兜底。
- 解锁与活动访问以服务端应用服务为权威；前端只把 DTO 映射为 Domain/ViewModel 并展示状态。
- Readiness、审计日志和运行时配置均在 DTO→ViewModel 边界做缺失/未知值归一化，避免原始工程字段泄漏。
- 性能优化以测量为前提，只处理已证实的串行加载、重复预取或慢查询，不做大范围重构。

## Decision (ADR-lite)

**Context**：当前故障横跨认证、活动编排、后台管理和客户端能力，且工作区已有相关未提交改动。  
**Decision**：采用基于现有架构的增量修复，服务端锁定规则权威化、客户端共享 UUID 兼容、边界 ViewModel 归一化，并以针对性回归测试锁定。  
**Consequences**：HTTP 下上传类写入可恢复，但真实麦克风、HTTPS 跳转和 TLS WebSocket 仍需后续域名配置验证；为避免覆盖 WIP，部分文件可能只补测试或围绕现有改动收敛。

## Out of Scope

- 正式域名、DNS、TLS 证书、反向代理 HTTPS 与 HTTP→HTTPS 强制跳转。
- 在不安全上下文中绕过浏览器对 `getUserMedia` 的限制。
- 真实 ASR/评分 Provider 和真实实时语音供应商的生产验收。
- 改动或清理现有生产训练数据、发布正式路径、创建不可回滚的测试对象。
