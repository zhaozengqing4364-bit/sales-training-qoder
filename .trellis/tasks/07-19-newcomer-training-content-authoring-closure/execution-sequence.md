# 执行顺序与质量门

## Wave 0：合同与事实基线

执行 `07-19-foundation-authoring-contract-inventory`。

进入下一阶段前必须满足：

- 新旧对象映射、唯一写权威和资源发布联合已冻结；
- API/领域/权限/迁移合同一致；
- 当前数据库 inventory 能稳定重跑；
- 原首发验收矩阵中的误报已被显式更正，而不是继续以“已有入口”代替“可配置”。

## Wave 1：资源生产能力

在 Wave 0 完成后推进：

- 多媒体内容资产；
- 题库与测验；
- 录音材料与评分；
- 结构化 AI 教练；
- 异步客户场景。

每个资源任务必须独立证明：逻辑对象 → working revision → validate → ReleasePlan 依赖 → published revision → 引用/归档保护。

## Wave 2：管理端与路径编排

执行管理信息架构和路径内资源绑定。

进入迁移前必须满足：

- 授权角色能从稳定导航找到其负责对象；
- 无权限不是空列表，后端仍拒绝越权；
- 五类 Activity 的所有必需资源都能在当前编辑上下文选择或快速新建；
- 学员预览与正式 Runtime 使用同一编译合同；
- 发布预览能指出缺失、过期、跨组织或未批准修订。

## Wave 3：迁移与切换

执行旧数据 inventory、dry-run、apply、verify 和旧写入口退役。

切换门：

- `石犀ppt讲解`、`demo讲解` 和对应 PPT 的映射明确；
- 重复执行迁移无重复对象/修订；
- 迁移 ReleasePlan 可预览、发布、回滚；
- 活跃 Enrollment 不被静默移动；
- Legacy 页面不再产生新人 Foundation 的竞争数据。

## Wave 4：端到端验收

只处理跨切片验收缺口，不借最终任务重构已完成切片。

必须证明：管理员配置真实材料和任务 → 组卷 → 配置评分/教练/场景 → 编排并发布路径 → 分配新人 → 新人完成学习、做题、录音、Coach、异步场景 → 管理员查看证据和复核。实时客户对练不得出现在验收路径。

## 停止条件

每个子任务验收通过后立即归档；不得因下游任务尚未开始而提前实现其内容。最终任务只在所有依赖均完成后启动。
