# 任务范围与测试约束

本文件对父任务及全部子任务具有约束力。

1. 只完成当前激活子任务明确要求的内容，不主动扩大范围。
2. 发现与当前子任务无关的问题时，只记录到该任务的 `implementation-notes.md` 并在交付时告知，不主动修复、不顺带重构。
3. 默认只运行与本次修改直接相关的最小测试：
   - 修改文件的静态检查；
   - 相关模块的单元测试；
   - 能证明本次修改正确的针对性集成、契约或浏览器验证。
4. 不得因为修改较小就主动运行全量测试、全量构建、全库扫描或全项目格式化。
5. 仅在以下情况允许执行全量测试：
   - 用户明确要求；
   - 修改涉及公共基础设施、核心依赖、全局配置或跨模块接口；
   - 局部测试无法证明修改安全。
6. 测试失败时先判断是否由本次修改引起。历史问题只记录证据，不在当前任务主动修复。
7. 当前子任务达到验收标准后立即停止，不继续额外优化、重构、清理或“顺便修复”。

核心原则：**最小修改、最小验证、完成即停止；后续问题进入后续任务。**

## 额外执行门

- 写代码前使用 CodeGraph 阅读目标链路、调用者和同类实现；共享合同变更前做 impact/affected 分析。
- 用户可见改动先读取 `DESING.md`、对应 Trellis 前后端规范和页面附近既有实现。
- 数据迁移必须先 `inspect -> dry-run -> apply -> verify`，并证明幂等、组织隔离、冲突处理和回滚。
- UI 完成声明必须包含实际渲染检查；只读代码或只跑组件测试不能替代关键路径页面检查。
- AI、评分、发布、权限与批量操作必须有失败、部分成功、审计和恢复证据。
