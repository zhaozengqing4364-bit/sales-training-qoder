# 商务礼仪训练包 v1 PRD

**日期**: 2026-06-14  
**状态**: 方案草案，待评审  
**来源资料**: `docs/lujingshuji/商务礼仪-新人的第一本职业素养手册-完整版.md`  
**所属产品**: 新人训练路径 / 商务技巧模块  
**核心决策**: PPT 演讲模块保持现状；本轮重点重构商务礼仪模块，将其从“文章 + 考试 + AI 教练入口”升级为“能力点达标系统”。

---

## Problem Statement

当前新人训练路径中的商务技巧模块已经具备文章学习、考试和 AI 教练入口，但产品主轴仍偏“完成内容”和“进入功能”。这不足以回答用户真正关心的问题：

1. 新人到底哪里没达标。
2. 管理者和带教人如何看到新人卡点。
3. 公司已有商务礼仪资料如何沉淀为可复用、可版本化、可训练、可审计的方法论资产。
4. 如何减少老员工反复讲同一套商务礼仪、拜访准备和表达分寸的带教成本。

因此，商务礼仪模块不能继续被建模为单篇长文章或一次性考试。它需要成为一个围绕能力点达标的训练包。

## Solution

建设“商务礼仪训练包 v1”：

```text
资料资产
  -> 文章/章节树
  -> 训练小单元
  -> 能力点模型
  -> AI 出题草稿
  -> 管理员审核发布
  -> 小单元测验
  -> AI 教练 ABD 训练卡
  -> 能力点达标判断
  -> 管理端卡点复盘
```

第一版按以下顺序全部实现：

1. 资料导入成文章 + 章节阅读。
2. 章节题目 AI 草稿箱 + 人审发布。
3. 小单元测验 + 能力点掌握度。
4. AI 教练工作台 + ABD 训练卡。
5. 管理端卡点视图。

PPT 演讲模块不改动，继续保留现有录音评分路径。

## Product Principles

1. **能力点是评价单位**：章节、题目、AI 教练卡和卡点视图都要绑定能力点。
2. **原文资产不乱改**：原始资料作为知识资产保留，训练编排在其上增加一层。
3. **AI 只生成草稿**：AI 题目、能力点建议和训练卡生成必须经过白名单、审核、版本和审计约束。
4. **教练不是聊天机器人**：AI 教练页面是训练工作台，不是通用聊天页。
5. **业务规则后台可配置**：小单元开放、通过标准、AI 教练是否必做、未达标处理、版本升级策略均不得写死。
6. **训练依据可追溯**：学员训练记录必须冻结资料版本、题目版本、能力点版本和 prompt 版本。

## User Stories

1. 作为新人学员，我想先看到 7 个训练小单元，而不是一整本书目录，以便知道自己要按什么路径完成商务礼仪训练。
2. 作为新人学员，我想进入小单元后看到原文章节，以便既能按训练节奏学习，也能追溯原始资料。
3. 作为新人学员，我想知道每个小单元训练哪些能力点，以便理解学习目标。
4. 作为新人学员，我想看到章节阅读进度，以便知道还有哪些内容没有完成。
5. 作为新人学员，我想完成一个小单元后进行小测，以便确认自己是否理解关键知识。
6. 作为新人学员，我想在小测后进入 AI 教练专项训练，以便把知识迁移到真实商务场景。
7. 作为新人学员，我想在 AI 教练中看到当前训练卡，而不是被消息流淹没，以便专注完成一次训练任务。
8. 作为新人学员，我想看到教练指出我做对了什么、哪里不合适、应该怎么改，以便下一次能改进。
9. 作为新人学员，我想在未达标时看到建议回看的章节和重练卡片，以便有明确补救路径。
10. 作为新人学员，我想看到“已达标 / 可上场”这类能力状态，以便知道自己是否可以进入下一阶段。
11. 作为复训人员，我想选择重练最新版训练包，以便在资料更新后重新校准能力。
12. 作为有经验员工，我想管理员能允许我跳过阅读直接小测或 AI 教练，以便减少重复学习成本。
13. 作为内容管理员，我想导入整套商务礼仪资料，并生成草稿版本，以便先预览再发布。
14. 作为内容管理员，我想保留原资料目录结构，以便资料仍然是可追溯知识资产。
15. 作为内容管理员，我想让 AI 建议训练小单元、能力点和题目草稿，以便降低内容生产成本。
16. 作为内容管理员，我想在 AI 出题草稿箱批量审核题目，以便控制 AI 产物质量。
17. 作为内容管理员，我想在章节编辑页看到该章节的 AI 题目草稿，以便就地审核和修改。
18. 作为内容管理员，我想审核题目的题干、答案、解析、能力点、难度和适用小单元，以便确保题目能作为达标依据。
19. 作为内容管理员，我想题目审核通过后才进入正式题库，以便学员不会看到未经确认的 AI 内容。
20. 作为培训负责人，我想配置每个小单元是否要求阅读、小测和 AI 教练，以便不同内容使用不同训练强度。
21. 作为培训负责人，我想配置小单元前置依赖、是否允许跳过、是否阻断后续单元，以便适配新人、复训人员和有经验员工。
22. 作为培训负责人，我想配置关键能力点通过线、最大训练卡数量和重练次数，以便训练强度可控。
23. 作为培训负责人，我想在资料新版发布前看到影响分析，以便知道会影响哪些章节、小单元、题目、能力点、AI 教练 prompt 和在学人员。
24. 作为培训负责人，我想发布新版时选择仅新学员生效、允许老学员自愿切换或指定人群重练，以便符合实际月度/双月更新节奏。
25. 作为带教人，我想看到新人卡在哪个能力点，而不是只看到分数，以便进行针对性辅导。
26. 作为带教人，我想看到新人最近几次回答和教练反馈证据，以便判断是否需要人工介入。
27. 作为带教人，我想看到系统建议怎么干预，以便减少我自己重新诊断的时间。
28. 作为管理员，我想查看训练包、题目、能力点、prompt、训练记录的版本历史和回滚记录，以便保证训练依据可解释。
29. 作为系统运维人员，我想 AI 生成失败、prompt 输出非法、配置缺失时有明确错误和兜底，以便问题可诊断而不是默默降级。
30. 作为审计人员，我想看到资料导入、AI 草稿生成、审核、发布、回滚、重练指派和人工复盘的操作记录，以便后续追责和复盘。

## Capability Model

第一版主能力点：

1. 尊重与分寸感。
2. 职业形象与仪态。
3. 见面社交动作。
4. 商务沟通表达。
5. 接待拜访准备与执行。
6. 会议洽谈秩序。
7. 餐饮应酬边界。
8. 失误补救与复盘内化。

每个能力点需要：

| 字段 | 要求 |
|---|---|
| `capability_key` | 稳定机器标识 |
| `display_name` | 后台可编辑展示名 |
| `description` | 能力解释 |
| `mastery_levels` | 未掌握 / 基本掌握 / 已掌握 / 可上场 |
| `default_threshold` | 默认达标线 |
| `evidence_rules` | 可作为证据的题目、训练卡、评分结果 |
| `owner_scope` | 所属训练包或通用能力 |
| `status` | 草稿、已发布、归档 |

能力点不可散落在前端组件中；必须由后端配置/资产体系读取。

### 能力点归属与快照边界

第一版能力点归属于“商务礼仪训练包版本”。管理员可以在草稿版本中编辑能力点名称、说明、达标线和证据规则；发布训练包时，系统冻结能力点快照，后续题目、小测、AI 教练训练卡、训练记录和卡点视图都引用该已发布快照。

第一版不建立独立的全公司通用能力点目录。若未来要把商务礼仪能力点沉淀为跨训练包通用能力，必须新增明确的能力目录归属、映射关系和快照规则，不能让学员历史记录直接引用可变全局配置。

## Question Draft Workflow

AI 出题流程：

```text
章节内容
  -> AI 生成题目草稿
  -> 出题草稿箱
  -> 章节页内联审核
  -> 管理员修订/拒绝/通过
  -> 正式题库
  -> 绑定章节 / 小单元 / 能力点
  -> 学员可见
```

AI 可以生成：

- 单选题。
- 多选题。
- 简答题。

AI 生成的题目必须保留：

- 来源章节。
- 来源片段。
- prompt 版本。
- 模型配置。
- 生成时间。
- 审核人。
- 审核结论。
- 修改前后 diff。

AI 题目不得自动发布。未审核题目不得进入学员端测验、AI 教练题源或达标计算。

## AI Coach Workbench

AI 教练人格：耐心教练。

页面形态：训练卡优先 + 工作台结构。

### 布局

- 左侧或顶部：当前小单元、当前能力点、掌握状态、本轮目标、薄弱原因。
- 中间：当前训练卡最大化。
- 右侧或下方：教练反馈区。
- 底部：自由追问或补充回答。
- 结束面板：本轮是否达标、下一步练什么。

### ABD 训练卡

优先支持：

1. 场景判断卡：给一个拜访/接待/会议/餐饮场景，让新人判断做法是否合适。
2. 改写卡：给一段不专业表达，让新人改成合适表达。
3. 角色回应卡：客户、领导或同事说一句话，新人写回应方式。

章后小测保持轻量，优先用单选、多选、简答。ABD 卡默认用于小单元 AI 教练和最终综合训练，是否启用由后台配置。

### 反馈结构

AI 教练每次反馈固定输出：

1. 你做对了什么。
2. 主要问题是什么。
3. 为什么在真实商务场景里不合适。
4. 可以怎么说。
5. 再试一版或进入下一张卡。

评价方式：

- 能力点评分。
- 掌握等级。
- 证据式反馈。

不允许只输出简单对错。

## Prompt Governance

提示词是核心资产，必须后台治理：

1. 教练角色提示词。
2. 能力点诊断提示词。
3. 训练卡生成提示词。
4. 评分提示词。
5. 补救策略提示词。
6. 输出格式约束提示词。
7. 安全边界提示词。

每个 prompt 需要：

- 模板 ID。
- 版本 ID。
- 状态。
- 适用训练包/小单元/能力点。
- 输出 schema。
- 测试样例。
- 发布人。
- 发布时间。
- 回滚入口。
- 操作日志。

AI 教练只允许输出后端白名单 typed UI events，不允许任意 JSX、HTML 或脚本。

所有 AI 出题、AI 教练训练卡生成、评分反馈和补救建议都必须经过现有 PromptTemplateService / prompt 模板治理链路解析模板、版本、schema 和 contract hash。业务服务只传入训练包、小单元、能力点、章节、题源和学员作答上下文，不直接拼接 prompt，不新增绕过 PromptTemplateService 的模型调用路径。

缺少已发布 prompt、prompt 版本失效、输出 schema 不匹配或 contract hash 不一致时，运行时必须 fail closed：返回明确错误并记录审计日志，不生成草稿题目、不推进训练卡、不写入达标结果。

## Versioning And Release

资料发布策略：

1. 每次导入生成草稿版本。
2. 已发布版本不被直接覆盖。
3. 发布前展示影响分析。
4. 支持版本历史、差异对比、回滚。
5. 已开始学习的学员默认继续旧版本。
6. 管理员可选择：
   - 仅新学员使用新版。
   - 允许老学员自愿切换新版。
   - 指定人群重练新版。

老学员自愿切换新版或被指定重练新版时，系统必须创建新的训练 attempt / session，并引用新版训练包快照；旧训练记录保留原始资料、题目、能力点、prompt 和卡片版本，不被覆盖或重写。旧记录可以标记为已完成、已归档或已放弃，但不得被新版结果原地替换。

影响分析必须覆盖：

- 改动章节。
- 受影响小单元。
- 受影响题目。
- 受影响能力点。
- 受影响 AI 教练训练卡。
- 受影响 prompt 绑定。
- 正在旧版本学习的学员。
- 建议重练范围。

## Implementation Decisions

1. 商务礼仪训练包是新人训练路径商务技巧模块下的训练包，不替代 PPT 演讲模块。
2. 原始资料与训练编排分层：原文作为知识资产，训练小单元作为学习路径。
3. 训练包、小单元、能力点、题目、prompt、AI 教练卡和训练记录都必须版本化或引用版本快照。
4. AI 出题走草稿箱，不直接写正式题库。
5. 正式题库仍是学员测验和 AI 教练可控抽题的默认来源。
6. AI 教练可实时生成训练卡，但必须符合白名单卡类型和 typed UI event schema。
7. AI 教练页面从聊天页升级为训练工作台，聊天输入只是辅助入口。
8. 小单元开放、跳过、阻断、通过线、重练、人工复盘阈值都必须由后台配置。
9. 发布新版资料时不覆盖历史训练记录，已开始训练的学员保留开始时版本快照。
10. 管理端卡点视图是训练闭环的一等入口，不是普通报表后置能力。
11. 能力点第一版归属于训练包版本快照，不做独立全局能力点目录。
12. AI 出题、AI 教练训练卡、评分和补救建议统一复用 PromptTemplateService / prompt 模板治理链路，不新增 prompt 渲染或模型调用旁路。
13. 自愿切换新版和指定重练新版都创建新的训练 attempt / session，历史训练记录只读保留。

## Testing Decisions

测试应验证外部行为，不绑定组件内部实现细节。

需要覆盖：

1. 资料导入生成草稿版本。
2. 原文 8 节映射为文章章节树。
3. 训练编排展示 7 个小单元。
4. 小单元开放规则、跳过规则和阻断规则。
5. AI 出题草稿生成、审核、拒绝、发布。
6. 未审核题目不可进入学员端。
7. 小单元测验结果映射能力点。
8. AI 教练只接受/输出白名单卡类型。
9. ABD 卡提交后输出能力点评分、掌握等级和证据反馈。
10. 未达标时推荐章节和重练卡。
11. 管理端卡点视图显示能力点、证据、干预建议。
12. 新版资料发布影响分析。
13. 已开始学习者保留旧版本；指定人群可重练新版。
14. 权限不足时不能修改训练包、题目、prompt 或发布版本。
15. 操作日志记录导入、审核、发布、回滚、重练指派和人工复盘。
16. 能力点发布后形成训练包版本快照，修改能力点不会改写历史训练记录。
17. AI 出题和 AI 教练运行时必须通过 PromptTemplateService 获取已发布模板；缺失或非法时 fail closed。
18. 老学员自愿切换新版会创建新训练记录，旧记录保留旧版本快照和原状态。

前端测试优先复用现有 sales-trainer 页面和 AI coach 测试模式。后端测试优先落在 sales_trainer 服务、API 和权限层。

## Out Of Scope

1. 不改 PPT 演讲模块。
2. 不实现实时 WebSocket 客户对练。
3. 不把 CopilotKit 作为训练工作台核心渲染层。
4. 不让 AI 自动发布题目或 prompt。
5. 不做全公司通用知识库导入系统，只做商务礼仪训练包所需的资料导入和版本管理。
6. 不一次性实现复杂多人审批流，第一版用管理员审核发布。
7. 不在前端组件硬编码能力点、题目、通过线、提示词或版本策略。

## Further Notes

这份 PRD 的核心不是“把一本书放进系统”，而是把商务礼仪资料转化为可训练、可判断、可复盘、可管理的新人能力达标体系。

后续实现时应优先保证资料版本、能力点、题目、AI 教练输出和训练记录之间的追溯关系。只要追溯关系稳定，UI、题目数量和提示词细节都可以迭代。
