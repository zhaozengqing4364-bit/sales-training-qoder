# 商务礼仪训练包 v1 分期实施任务

**日期**: 2026-06-14  
**状态**: 方案草案，待评审  
**父级 PRD**: `docs/plans/2026-06-14-business-etiquette-training-pack-prd.md`

---

## 审计补充契约

本补充关闭 2026-06-14 方案审计发现的 3 个非阻塞缺口，后续开发必须先按这些契约实现，避免形成新的旁路。

1. **能力点归属**：第一版能力点归属于商务礼仪训练包版本快照。允许在草稿版本编辑，发布后冻结；题目、小测、AI 教练、训练记录、卡点视图都引用已发布快照。第一版不新增独立全局能力点目录。
2. **Prompt 治理链路**：AI 出题、AI 教练训练卡、评分反馈、补救建议全部复用现有 PromptTemplateService / prompt 模板治理，不新增绕过治理的 prompt 拼接或模型调用路径。
3. **新版重练记录**：老学员自愿切换新版或被指定重练新版时，创建新的 training attempt / session；旧记录保留旧版本快照，不被新版结果覆盖。

---

## 总体顺序

按已确认顺序推进：

1. 资料导入成文章 + 章节阅读。
2. 章节题目 AI 草稿箱 + 人审发布。
3. 小单元测验 + 能力点掌握度。
4. AI 教练工作台 + ABD 训练卡。
5. 管理端卡点视图。

每期必须端到端可验证，不做只落后端或只落前端的悬空能力。

## Slice 1: 训练包资料导入与版本草稿

**Type**: AFK  
**Blocked by**: None  
**覆盖用户故事**: 13, 14, 23, 28, 30

### What to build

支持管理员将商务礼仪 Markdown 导入为训练包资料草稿版本。系统保留原始资料结构，解析出全书、8 个原始章节、H2 微章节和 H3 知识点。导入后不影响学员端，必须由管理员预览和发布。

### Acceptance criteria

- [ ] 管理员可以上传或选择 Markdown 文件生成商务礼仪训练包草稿版本。
- [ ] 系统解析标题层级，保存原始章节、微章节和知识点。
- [ ] 草稿版本包含来源文件、内容 hash、导入人、导入时间。
- [ ] 已发布版本不会被导入覆盖。
- [ ] 导入失败返回明确错误，不生成半成品版本。
- [ ] 写入操作日志。
- [ ] 有后端服务测试和前端导入/预览测试。

### 配置化要求

- 支持的导入格式、最大文件大小、是否允许覆盖草稿、默认训练包 key 均为配置。
- 缺少导入 prompt 或解析配置时，导入只能做结构解析，不做 AI 建议。

## Slice 2: 7 个训练小单元编排与学员端阅读

**Type**: AFK  
**Blocked by**: Slice 1  
**覆盖用户故事**: 1, 2, 3, 4, 20, 21

### What to build

在原始资料层之上增加训练编排层。学员端商务礼仪第一屏展示 7 个训练小单元，点进小单元后查看对应原文章节和阅读进度。小单元开放规则由后台配置。

### Acceptance criteria

- [ ] 学员端展示 7 个训练小单元，而不是直接展示 8 节书目录。
- [ ] 小单元详情页展示本单元覆盖章节、能力点、阅读进度和下一步 CTA。
- [ ] 管理员可配置小单元顺序、标题、描述、章节绑定、是否启用。
- [ ] 管理员可配置前置依赖、是否允许跳过阅读、是否阻断后续单元。
- [ ] 默认新人按顺序推进。
- [ ] 复训/豁免策略可由后台配置，不硬编码角色。
- [ ] 学员阅读记录引用资料版本。
- [ ] 有小单元配置测试、学员阅读测试和权限测试。

### 配置化要求

- 小单元标题、描述、开放策略、跳过策略、前置依赖、空状态文案均为配置。
- 缺失小单元配置时，学员端显示不可用和管理员修复入口，不猜测生成。

## Slice 3: 能力点模型与章节/小单元绑定

**Type**: AFK  
**Blocked by**: Slice 2  
**覆盖用户故事**: 3, 18, 22, 25, 28

### What to build

建立商务礼仪能力点模型。管理员可以管理 8 个主能力点，并将能力点绑定到章节、小单元、题目和 AI 教练训练卡。能力点用于后续测验、AI 教练和管理卡点视图。

### Acceptance criteria

- [ ] 后台可创建、编辑、发布、归档能力点。
- [ ] 默认导入 8 个主能力点草稿或 seed。
- [ ] 小单元可绑定一个或多个能力点。
- [ ] 章节可绑定一个或多个能力点。
- [ ] 能力点包含达标线、掌握等级、证据规则。
- [ ] 已发布能力点不可被静默破坏，修改走新版本或草稿。
- [ ] 发布训练包时冻结能力点快照；学员记录、题目、小测、AI 教练和卡点视图引用该快照。
- [ ] 第一版不建立独立全局能力点目录；如未来需要通用能力目录，另建映射和快照契约。
- [ ] 学员端展示小单元能力点。
- [ ] 权限不足不能修改能力点。

### 配置化要求

- 能力点名称、说明、等级、阈值、证据规则均可配置。
- 缺少能力点绑定的小单元不得发布为“需达标”类型。
- 能力点配置缺失或非法时训练包不可发布，不由前端兜底生成能力点。

## Slice 4: AI 出题草稿箱

**Type**: HITL  
**Blocked by**: Slice 1, Slice 3  
**覆盖用户故事**: 15, 16, 17, 18, 19, 30

### What to build

从章节内容生成单选、多选、简答题草稿。AI 题目先进入草稿箱，管理员可以批量审核，也可以在章节编辑页内联审核。草稿未通过审核前不得进入正式题库。

### Acceptance criteria

- [ ] 管理员可对单章或多章触发 AI 出题。
- [ ] AI 出题结果进入草稿箱，状态为待审核。
- [ ] 草稿记录来源章节、来源片段、能力点建议、题型、答案、解析、prompt 版本、模型配置。
- [ ] 草稿箱支持筛选：章节、题型、能力点、状态、生成批次。
- [ ] 章节编辑页可看到本章草稿。
- [ ] 管理员可通过、拒绝、编辑草稿。
- [ ] 通过后写入正式题库并绑定章节/能力点。
- [ ] 拒绝后保留原因和审计记录。
- [ ] AI 出题必须通过现有 PromptTemplateService 获取已发布 prompt、schema 和 contract hash。
- [ ] AI 输出非法时返回明确错误，不写入草稿箱。

### HITL 点

需要人工评审 AI 出题 prompt、题目质量标准、题型比例和草稿审核 UI 是否符合运营习惯。

### 配置化要求

- 每章默认题型数量、题型白名单、难度、能力点绑定策略、prompt 模板均为配置。
- AI 生成失败时可重试，但不得自动发布。

## Slice 5: 小单元测验与能力点掌握度

**Type**: AFK  
**Blocked by**: Slice 3, Slice 4  
**覆盖用户故事**: 5, 10, 20, 22, 23

### What to build

每个小单元结束后可进行小测。测验从已审核题库抽题或绑定题目，提交后根据题目能力点计算小单元掌握度和能力点掌握等级。

### Acceptance criteria

- [ ] 小单元可配置是否需要小测。
- [ ] 小测只使用已发布题目。
- [ ] 题目必须绑定能力点，否则不可作为达标依据。
- [ ] 提交后生成小单元测验记录。
- [ ] 系统计算能力点分数和掌握等级。
- [ ] 达标线从能力点/小单元配置读取。
- [ ] 未达标时展示薄弱能力点和建议回看章节。
- [ ] 测验记录冻结资料版本、题目版本和能力点版本。
- [ ] 管理员可查看小测结果。

### 配置化要求

- 题目数量、题型比例、通过线、是否允许重测、重测次数均为配置。
- 配置非法时小单元不可发布。

## Slice 6: AI 教练 prompt 体系与 typed 训练卡契约

**Type**: HITL  
**Blocked by**: Slice 3, Slice 5  
**覆盖用户故事**: 6, 7, 8, 18, 29, 30

### What to build

定义 AI 教练的 prompt 资产、输出 schema 和 ABD 训练卡 typed event 契约。AI 教练只能使用白名单训练卡，不允许任意 JSX/HTML。

### Acceptance criteria

- [ ] 后台可管理教练角色、能力诊断、训练卡生成、评分、补救策略、输出格式、安全边界 prompt。
- [ ] prompt 支持版本、发布、回滚、测试样例和操作日志。
- [ ] 定义 ABD 卡输出 schema：场景判断卡、改写卡、角色回应卡。
- [ ] 定义反馈 schema：做对了什么、主要问题、为什么不合适、可以怎么说、下一步。
- [ ] AI 输出不符合 schema 时拒绝并记录错误。
- [ ] 运行时记录 prompt 版本和 contract hash。
- [ ] 教练训练卡生成、评分反馈和补救建议都通过现有 PromptTemplateService，不新增 prompt 渲染旁路。
- [ ] 前端只渲染注册卡片类型。

### HITL 点

需要人工评审 prompt 设计、反馈语气和训练卡样例。AI 教练人格确认：耐心教练为主，先肯定再纠正，给示范，少量追问。

### 配置化要求

- prompt 模板、卡片类型白名单、最大卡片数、重试次数、超时、补救策略均为配置。
- 缺少已发布 prompt 时，AI 教练入口不可用。

## Slice 7: AI 教练训练工作台

**Type**: AFK  
**Blocked by**: Slice 6  
**覆盖用户故事**: 6, 7, 8, 9, 10

### What to build

将当前聊天页升级为训练卡优先的工作台。页面围绕当前小单元、能力点、训练卡和教练反馈组织，底部保留自由输入作为辅助。

### Acceptance criteria

- [ ] 页面显示当前小单元、能力点、掌握状态、本轮目标。
- [ ] 当前训练卡是主视觉，不被聊天消息流淹没。
- [ ] 支持场景判断卡、改写卡、角色回应卡。
- [ ] 支持提交训练卡答案。
- [ ] 提交后展示结构化反馈。
- [ ] 支持自由追问，但自由追问不绕过训练卡状态机。
- [ ] 结束面板展示本轮能力点是否达标、为什么、下一步。
- [ ] 移动端和桌面端布局可用。
- [ ] 前端测试覆盖卡片渲染、提交、反馈、结束状态。

### 配置化要求

- 页面文案、按钮文案、是否显示自由追问、是否允许跳过卡片均由配置控制。

## Slice 8: AI 教练达标判断与补救流

**Type**: AFK  
**Blocked by**: Slice 6, Slice 7  
**覆盖用户故事**: 8, 9, 10, 22, 24, 25

### What to build

AI 教练训练完成后，根据能力点评分、掌握等级和训练证据判断小单元是否达标。未达标时推荐回看章节、重练卡片，并可进入待人工复盘。

### Acceptance criteria

- [ ] 训练卡结果写入能力点得分和掌握等级。
- [ ] 小单元 AI 教练完成条件从配置读取。
- [ ] 默认关键能力点达到“基本掌握”即小单元已达标。
- [ ] 达到“可上场”条件时展示最高等级。
- [ ] 未达标时推荐回看章节和重练卡片。
- [ ] 超过最大重练次数仍未达标时进入待人工复盘。
- [ ] 是否阻断后续小单元由配置决定。
- [ ] 训练记录冻结 prompt、卡片、题源、资料和能力点版本。

### 配置化要求

- 训练完成条件、能力点通过线、重练次数、阻断策略、人工复盘阈值均为配置。

## 建议里程碑

包含 Slice 1-3。目标是让商务礼仪资料成为可版本化训练包，并能在学员端按 7 个小单元阅读。

包含 Slice 4-5。目标是形成 AI 出题草稿、人审发布、小单元测验和能力点掌握度。

### Milestone 3: AI 教练训练工作台

包含 Slice 6-8。目标是把 AI 教练从聊天页升级为能力训练工作台。

包含 Slice 9-10。目标是支持真实运营中的版本更新、重练策略和带教干预。

包含 Slice 11。目标是形成可演示、可回归、可上线的完整闭环。

## 技术注意事项

1. 所有 learner API 必须只返回已发布且对当前学员生效的版本。
2. 所有训练记录必须冻结资料、题目、能力点、prompt 和卡片版本。
3. 能力点第一版归属于训练包版本快照，不新增独立全局能力点目录。
4. AI 出题、AI 教练训练卡、评分反馈和补救建议必须复用现有 PromptTemplateService / prompt 模板治理链路。
5. 老学员自愿切换新版或指定重练新版必须创建新的 training attempt / session，不覆盖旧记录。
6. 前端不得直接拼业务 API，继续通过集中 API facade 调用。
7. AI 教练不得渲染任意 JSX/HTML，只能渲染 typed card。
8. 题目、能力点、通过线、开放规则、补救策略、文案都不得硬编码在页面组件中。
9. 权限判断集中在后端能力投影和具体 API，不在多个前端页面复制角色矩阵。
10. 管理端新增发布、回滚、审核、重练指派时必须写操作日志。
11. 未发布或配置非法时学员端 fail closed，展示可操作错误，不伪装可用。
