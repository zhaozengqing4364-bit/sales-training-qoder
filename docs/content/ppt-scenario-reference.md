# 新员工 AI 对练最小启动场景

来源：`新员工AI对练场景清单.xlsx` 复制文本。

用途：

- 作为新人训练路径训练素材的只读资料池。
- 第 1 关 `PPT讲解` 只使用其中“主胶片讲解（精华版）”相关内容；实际配置见 `docs/content/ppt-explanation-training-material.md`。
- 其余条目暂不作为 9 个 AI 教练场景导入数据库。
- 参考答案用于标杆表达，不要求学员逐字背诵；AI 评分应优先判断“是否完成场景目标、是否表达准确、是否能推进客户下一步”。

## 配置字段建议

每个场景建议拆成以下结构，方便后续导入数据库或后台配置：

| 字段 | 含义 |
|---|---|
| `scenario_key` | 稳定英文 key，用于配置和日志 |
| `training_stage` | 培训环节 |
| `title` | 对练场景标题 |
| `customer_profile` | 面向客户对象 |
| `drill_goal` | 主要演练方向 |
| `task_brief` | 学员看到的任务简报 |
| `scoring_standard` | AI 评分关注点 |
| `reference_answer` | 标杆表达参考 |

## 通用评分标准

总分建议 100 分，通过线建议 70 分。

| 维度 | 分值 | 评分说明 |
|---|---:|---|
| 场景目标完成度 | 25 | 是否完成本场景要求的核心任务，例如介绍、邀约、讲解、异议处理或下一步推进 |
| 业务信息准确性 | 25 | 是否准确表达石犀定位、数据流动治理、部署方式、案例、差异化，不夸大、不编造 |
| 表达结构与逻辑 | 20 | 是否有清晰顺序，能让客户听懂背景、问题、方案、价值、证据和行动 |
| 客户意识 | 15 | 是否贴合客户角色与处境，能回应技术、业务、决策或竞品关注点 |
| 语言自然度 | 10 | 是否像真实销售沟通，避免背稿、空话、堆术语 |
| 下一步推进 | 5 | 是否自然提出演示、扫描、约访、试点等可执行动作 |

### 一票扣分项

- 编造客户案例、性能指标、政策要求或产品能力。
- 明显贬低竞品或客户现有投入。
- 对安全合规、信创、部署方式作出无法兑现的承诺。
- 只复述产品功能，没有回应客户场景。
- 没有任何下一步行动建议。

## 场景 1：一段话介绍石犀

| 项目 | 内容 |
|---|---|
| 培训环节 | 初次介绍 |
| 面向客户对象 | 初次接触的客户（不分角色） |
| 主要演练方向 | 一分钟内讲清楚：石犀是谁、能解决什么问题、差异化在哪 |

### 任务简报

你正在第一次接触客户。请用一段话介绍石犀，让对方快速明白公司定位、核心能力、能解决的问题和差异化价值。

### 评分关注点

- 是否讲清楚“石犀是谁”：数据流动治理平台提供商。
- 是否讲清楚“解决什么问题”：看清数据资产、监控数据流动、防住风险、追溯泄露源头。
- 是否包含关键可信信息：总部、团队规模、研发占比、行业客户、典型案例。
- 是否能在一分钟内完成，表达紧凑但不生硬。

### 参考答案

石犀科技是一家专注数据流动治理的平台提供商，总部深圳，团队300+人，研发占60%。我们在国内首创“数据流动治理”理念，核心产品是数据流动治理平台，以“资产+用户”识别为抓手，以数据流动过程治理为核心。

平台能自动梳理业务系统 API 资产、用 AI 做数据分类分级（准确率超 91%，3 分钟处理 10 万+字段）、实时监测敏感数据泄露和 API 风险，并通过访问控制、脱敏、水印等 30+ 组件一键防护。

我们已服务政府、医疗、金融、教育等行业客户，落地案例包括深圳航空、深圳市大数据资源管理中心、北京卫健委、汕头大学等。

一句话：帮客户看清楚数据资产、监控好数据流动、防得住数据风险、追得到数据泄露源头。

## 场景 2：主胶片讲解（精华版）

| 项目 | 内容 |
|---|---|
| 培训环节 | 技术认可 |
| 面向客户对象 | 有明确需求的技术 / 业务负责人 |
| 主要演练方向 | 按 PPT 逻辑流畅讲解方案，5 分钟内不跳页、不遗漏关键内容 |

### 任务简报

你正在给有明确需求的技术或业务负责人做主胶片精华版讲解。请在 5 分钟内按照 PPT 逻辑讲清背景、方案核心、四步能力、差异化和部署方式。

### 评分关注点

- 是否有完整讲解结构：背景、方案核心、资产、分类分级、风险监测防护、溯源审计、差异化、部署。
- 是否能把“资产-用户-流动管控”作为主线讲清楚。
- 是否能自然带入案例，不只是罗列功能。
- 是否能讲清“平台+组件”相对传统设备堆叠的差异。
- 是否控制在 5 分钟内，不跳关键内容。

### 参考答案

大家好，我是石犀的销售经理，今天用几分钟介绍我们数据流动治理方案。

【背景】国家数据局成立推动数据要素市场化，等保新规已把数据安全纳入强制要求，数据安全有一项高风险，等保不通过。工信部今年要推动 4.5 万家企业做数据分类分级，合规是刚需；数据变现是未来的大趋势。

【方案核心：三位一体】我们的核心逻辑是“资产—用户—流动管控”：

第一步，资产自动盘点。设备旁路接入交换机镜像口，无需改任何业务系统，就能自动梳理出所有应用系统、API 接口、数据库。汕头大学通过我们梳理了 1000+ 的 API 资产，发现了大量未知业务系统。

第二步，AI 分类分级。我们自研的本地化 AI 模型（训练数据基于维基百科），分类准确率超 91%，3 分钟可处理 10 万+字段。以前人工做分类要几个月，现在缩短到天级。在华中农业大学，我们快速梳理了科研数据分类；在汕头大学，发现了教务系统的越权漏洞。

第三步，风险监测和防护。实时识别弱密码、敏感数据泄露、API 未鉴权、越权访问、数据出境等风险。然后通过组件一键处置，脱敏、水印、加密、访问控制，不需要改业务系统代码。譬如劲牌酒业案例中，我们通过代理模式解密 HTTPS 流量，识别出旅客信息泄露风险并实现实时阻断。

第四步，溯源审计。全量记录数据访问行为，一旦出事能精确追溯到谁、什么时间、通过什么方式、访问了什么数据。北京卫健委就是用我们的溯源能力解决了其他厂家搞不定的数据泄露追查。

【差异化：平台+组件 vs 设备堆叠】传统安全厂家是按功能卖设备，脱敏一台、WAF 一台、审计一台，串成“糖葫芦”，单点故障多、扩容贵。我们是平台+组件模式：一个平台，30+ 安全组件按需订阅。需要什么功能装什么组件，取消订阅就不收费。

部署上也灵活，镜像模式旁路无侵入（1-3 天上线），代理模式可解密 HTTPS 做实时防护。支持信创环境（主流，且可快速完成适配），已通过信创验收。

### 任务简报

你正在给陌生潜在客户打第一次电话。请完成自然开场、简短价值传递、处理一次常见异议，并争取一次半小时交流或演示机会。

### 评分关注点

- 是否开场简洁，有礼貌，不拖沓。
- 是否用客户能听懂的语言表达价值，而不是直接堆产品功能。
- 是否能处理“我们已有安全设备”这类异议。
- 是否提出清晰下一步：约访、演示、快速扫描。

### 参考答案

您好，请问是 XX 总吗？我是石犀科技的销售 XXX，冒昧打扰一分钟。

石犀是做数据安全这块的，主要帮企业做数据资产的自动盘点、数据分类分级，还有 API 和数据流动过程中的安全监控。我们总部在深圳，团队 300 多人，已经服务了政府、医疗、金融、教育这些行业的客户。

最近有个趋势想跟您同步：国家数据局成立后在大力推数据要素市场，等保新规今年 6 月开始数据安全变成强制项，数据安全有高风险项，等保直接不通过。另外工信部今年要推动 4.5 万家企业做数据分类分级，这块合规压力很大。

很多单位自己都不清楚内部到底有多少个业务系统、有哪些数据在流动、存在什么风险。我们只要把设备旁路接上去，一两天就能帮您出一份完整的数据安全风险报告。

【异议】

客户：我们已经有网络安全设备了，防火墙、IPS、WAF 都有。

理解，这些网络安全设备肯定是有价值的。不过我们做的跟它们不一样。防火墙等设备防的是网络层攻击，我们看的是数据层和业务逻辑层的风险。

举个例子：一个员工用合法账号在正常工作时间通过 API 大量拉取客户数据，传统安全设备看到是正常请求不会报警，我们的平台能通过行为分析发现这个异常。我们在深航就是跟 WAF 协同部署的，WAF 阻断攻击流量，我们治理数据流动风险，形成纵深防御。

要不我下周过来给您做个半小时的交流演示？可以带一套便携设备先做一个快速扫描，完全不影响现有业务。

## 场景 4：Demo 操作讲解

| 项目 | 内容 |
|---|---|
| 培训环节 | 技术认可 |
| 面向客户对象 | 有技术背景的客户（IT / 安全工程师、技术负责人） |
| 主要演练方向 | 操作流畅、讲解与操作同步、结合实际场景说明每个步骤的意义 |

### 任务简报

你正在给技术客户演示平台 Demo。请边操作边解释每个模块的意义，让客户理解资产发现、分类分级、风险审计和一键防护之间的关系。

### 评分关注点

- 是否能做到“操作到哪里，讲解到哪里”。
- 是否解释每个模块对客户有什么价值。
- 是否能通过具体风险例子说明传统设备看不到的问题。
- 是否能串起“发现风险 → 一键防护”的闭环。

### 参考答案

（边说边操作）大家好，我现在打开平台演示一下实际效果。

先看资产模块。大家注意，我们的设备只需要旁路接入交换机做流量镜像，不需要改任何业务配置。接入后它自动开始梳理，左边是自动发现的应用系统列表，包括每个系统有多少 API 接口、哪些有风险、哪些是正常状态。

点进一个应用系统，可以看到具体的 API 列表，每个 API 的状态。比如这里显示“弱密码”，我们点进去看详情：这个 API 返回了一个明文密码 123456，而且登录成功了。这个风险非常大，攻击者用这个密码去遍历就能登录系统。传统 WAF 能看到有人访问了这个 API，但看不到里面返回了什么内容，所以发现不了这类问题。

（切换到数据库模块）再看数据分类分级。我们 AI 模型自动扫描数据库，给每个字段打标签，这是姓名、这是身份证号、这是手机号，然后自动定级别。某政府单位原来人工做分类要几个月，我们用 AI 几个工作日就完成了。

（切换到审计模块）风险审计这里，所有异常行为都会实时出现，包括 API 未鉴权、敏感数据泄露、越权访问。还可以做溯源：如果有人泄露了数据，我们反向追溯是哪个账号、什么时间、通过什么方式操作的。然后再做正向排查他还有没有其他异常行为。

（切换到治理模块）最后看防护。假设我们发现某个页面上展示了客户手机号，直接在平台上加一个脱敏组件，把中间四位打码，不需要改业务系统代码。再比如发现爬虫攻击，加一个频控插件，限制单个 IP 的请求频率。在深航空护网期间，我们就通过频控+封禁阻挡了 1000+ 扫描 IP。

这就是我们的核心能力：发现风险 → 一键防护，全程不影响业务。

## 场景 5：模拟客户拜访（综合）

| 项目 | 内容 |
|---|---|
| 培训环节 | 综合演练 |
| 面向客户对象 | 甲方客户（含技术、业务、决策者多种角色） |
| 主要演练方向 | 开场破冰 → 需求探询 → 方案讲解 → 异议处理 → 下一步行动，全流程 15 分钟 |

### 任务简报

你正在进行一次完整客户拜访。请完成开场、需求探询、方案讲解、异议处理和下一步行动建议。目标不是背稿，而是像真实销售一样推进交流。

### 评分关注点

- 是否有开场和议程感。
- 是否先问客户现状，再讲方案。
- 是否能把方案压缩成客户能理解的 5 分钟版本。
- 是否能处理“已有数据库审计”等异议。
- 是否能提出低风险下一步，例如旁路扫描或风险评估报告。

### 参考答案

（开场）X 总您好，感谢各位的时间。今天主要想了解一下咱们在数据安全方面的现状和需求，然后也给大家展示一下我们的解决方案。

（需求探询）先请教几个问题：咱们单位目前大概有多少个业务系统在跑？对数据资产有没有做过完整的盘点和分类分级？现在国家数据局的政策推进很快，各行业都在推动做分类分级，如果没做的话会被通报扣分。另外日常的数据流动风险，比如 API 有没有未鉴权的问题、有没有敏感数据明文传输、有没有数据出境的管控需求，这些目前在关注吗？

（方案讲解，5 分钟）好，基于刚才交流，我快速介绍一下我们的方案。石犀的核心逻辑：先把数据资产和用户身份看清楚，再在数据流动中做实时监控和防护。

具体四步：第一，资产自动盘点，旁路镜像，1-3 天出结果，不改任何业务。第二，AI 分类分级，本地化 AI 模型，准确率超 91%，3 分钟处理 10 万+字段。第三，风险监测，弱密码、敏感数据泄露、API 未鉴权、越权访问、数据出境。第四，一键防护，通过 30+ 安全组件直接在平台上处置，不需要改业务系统代码。

（异议处理）

客户：我们已经有数据库审计了，不需要另外的设备。

说得很对，数据库审计在数据库层面确实有用。但现在数据泄露的路径变了。攻击者很少直接攻数据库，更多是通过正常应用系统、合法 API 通道做不合理的数据提取。纯数据库审计看不到应用层的这个盲区。

我们跟数据库审计是互补关系。它解决数据库层面的访问控制，我们解决应用层到数据库全链路的监控和防护。你们现有的投资不会浪费，但应用层的盲区需要补上。

我们在北京卫健委有个案例：数据泄露后找了好几家安全厂家都没找到源头，因为他们只看到合法 IP 和账号在访问。我们通过对应用层和 API 层的深度解析加行为分析，最终定位到了泄露者。

（下一步）今天我们可以先做一个快速演示。如果感兴趣，可以选 1-2 个非核心业务系统做一次旁路扫描，3 天左右出一份数据安全风险评估报告，完全零风险。您觉得怎么样？

## 场景 6：客户分层沟通

| 项目 | 内容 |
|---|---|
| 培训环节 | 初次介绍 |
| 面向客户对象 | 技术负责人（如 CISO、安全总监） |
| 主要演练方向 | 用技术语言讲方案：强调安全合规、技术架构、部署方式、对业务无侵入 |

### 任务简报

你正在向 CISO 或安全负责人介绍石犀方案。请从技术架构、部署方式、性能、安全合规、信创适配和客户案例角度说明价值。

### 评分关注点

- 是否能使用技术负责人听得懂的语言，而不是泛泛销售话术。
- 是否明确零侵入、旁路部署、代理模式、HTTPS 解密、本地化 AI、组件化防护等关键点。
- 是否准确表达性能、信创、国密、部署周期等信息。
- 是否能给出政府、医疗、教育、企业客户画像。

### 参考答案

X 总您好，今天重点从技术架构和合规角度跟您汇报一下石犀的方案。

【部署架构】石犀是旁路部署的数据流动治理平台，核心引擎部署在核心交换机侧，通过流量镜像完成全量数据采集。对业务系统零侵入、零改造，不需要在业务服务器上装 Agent，不需要改网络拓扑，不需要改应用代码。支持物理机、虚拟化和容器化（K8s）部署。

【技术栈】底层是自研的深度包解析引擎，能把 HTTP/HTTPS 流量还原到应用层协议字段级别。代理模式下可以解密 HTTPS（需导入证书），做全内容分析。中间层是我们训练的数据分类分级大模型，本地化部署，数据不出网，分类准确率超 91%，3 分钟处理 10 万+字段。上层是 30+ 安全组件全部容器化，按需加载，包括 ACL 访问控制、数据脱敏、频控、CC 防护、爬虫检测、熔断降级等。

【性能指标】支持分布式集群部署，实测最大单引擎处理 40Gbps 无业务感知延迟。软件 Bypass 机制确保 CPU 过载时流量透传，业务零中断。

【合规对标】完全对标等保 2.0 数据安全扩展要求，以及工信部工业数据安全分类分级标准。等保新规已明确数据安全一票否决。平台可以帮客户完成数据安全合规的自动化举证，分类分级报告、风险评估报告、整改报告一键导出。

【信创适配】已通过信创验收。兼容鲲鹏、飞腾、银河麒麟；平台支持对用户侧国产化数据库（达梦、人大金仓、海量等）进行扫描检测。深圳市大数据资源管理中心已在鲲鹏+麒麟环境下部署处理 2.5Gbps 政务云流量。支持 SM2/SM4 国密算法。

【模式选择】镜像模式用于审计监测（1-3 天上线，解密 HTTPS），代理模式用于实时防护（可解密 HTTPS、毫秒级阻断，部署约 1-2 周）。

【客户画像】目前主要客户分布在政府（罗湖政数局、广州海事法院等）、医疗（深圳慢性病防治中心、龙华区人民医院等）、教育（华中农业大学、汕头大学等）、企业（劲酒集团、深圳航空等）。

总结：零侵入、全覆盖、自动化、信创合规，帮客户在不改造现有系统的前提下实现从资产盘点到风险防护的全链路数据安全能力。

## 场景 7：异议处理实战

| 项目 | 内容 |
|---|---|
| 培训环节 | 需求挖掘 |

### 任务简报

客户已经有其他安全厂商方案，例如美创。请先肯定客户现有投入，再解释石犀与数据库安全方案的互补关系，最后提出低风险验证方式。

### 评分关注点

- 是否先尊重客户和竞品，不直接否定。
- 是否讲清数据库层面与应用/API 层面的差异。
- 是否能用真实案例说明为什么需要横向全链路监控。
- 是否能把“替换”转成“互补”，降低客户防御心理。

### 参考答案

客户：你们这个产品听着不错，但我们已经有美创的方案了，投入也不小。

学员回应：

感谢您的坦诚，美创在数据安全领域确实有很深的积累，尤其在数据库审计和脱敏这块做了十几年，客户量很大，这个我们非常尊重。

不过我想分享一个我们观察到的趋势：过去几年，数据泄露的主路径已经变了。

以前数据安全的核心战场是数据库，DBA 导出、数据库直接攻击。美创的数据库审计、数据库防火墙这些产品，在数据库层面做得非常成熟。

但现在我们发现，80% 以上的数据泄露是走应用层和 API 层的。员工用正常账号登录业务系统，通过合法 API 接口，一批一批地把数据拉出来。在数据库层面看，这些都是合法的正常操作，数据库审计不会报警。

这就是石犀跟美创的关键差异：

美创做的是“纵向深度”，在数据库这一个层面做到极致。

石犀做的是“横向全链路”，从用户出发，经过应用层、API 层，一直到数据库，全程监控。

我们有一个实际案例：北京卫健委数据泄露后，找了好几家包括数据库安全厂家都没找到源头，因为他们只看数据库访问，全部是合法操作。我们通过对应用层行为模式的分析，结合 API 调用频率、时间规律、数据量的异常组合，最终定位到了泄露者。

所以我一直跟客户说的不是“替换”，而是“互补”：

你们的数据库安全投资不会浪费，它继续守住数据库这最后一道关。但应用层和 API 层的监控需要补上，这样才能形成从入口到出口的完整防线。

我们在深智城就是跟 WAF 和数据库审计协同部署的，各司其职，形成纵深防御。

建议我们可以先做一个快速的旁路扫描，看看目前应用层和 API 层存在哪些风险是现有设备没有覆盖到的，完全不影响现有系统。您觉得呢？

X 总，您这个对比非常合理，美创在数据库安全领域确实做得很久，同行案例多也是客观事实，这个我们必须认。

美创做的是“纵向深度”，在数据库一个层面做到极致，这是他们的优势。

石犀做的是“横向全链路”，从用户登录开始，经过应用层、API 层，一直到数据库，全程监控行为模式。

所以我给客户的建议不是“在美创和石犀之间选一个”，而是“美创守住数据库这个纵向阵地，石犀补上应用和 API 这个横向盲区”。两个不是竞争，是纵深防御的两层。

如果感兴趣，我们可以先做一个快速扫描，看看在应用层和 API 层到底有哪些风险是现有方案看不到的，完全不影响业务和已有投入。您觉得呢？
