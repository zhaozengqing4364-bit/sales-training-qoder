# 一、项目总览

## 1. 项目名称

- **用户侧名称**：新人训练路径
- **内部技术名称**：`sales_trainer` / `sales-trainer`
- **API 命名空间**：`/api/v1/sales-trainer`
- **全称**：企业级 AI 销售训练系统

## 2. 项目定位

面向企业销售新人培训的 AI 驱动异步训练平台，聚焦「学-练-测-评」闭环中的异步学习场景。

**已覆盖范围**：
- 训练单元与路径配置
- 考卷 / 文章类内容训练
- 录音提交、ASR 转写、AI 评分与结果反馈
- 管理端内容生产、发布、归档、回滚
- 训练记录、评分结果、操作日志查看

**明确不包含**：
- 实时 WebSocket 语音对练（模块 4「实时对练」为 disabled / coming-soon 占位）
- 与 `sales_bot` 实时对练模块的创建或调用

## 3. 目标用户

| 角色 | 使用端 | 主要职责 |
|---|---|---|
| 销售新人 / 学员 | 学员端（C 端） | 按训练路径完成单元学习、考卷、文章阅读、录音训练并查看评分结果 |
| admin / super_admin / content_admin / newcomer_content_admin | 管理端 | 内容管理：训练单元、考卷、材料库、录音评分标准、新人训练路径、AI Coach 配置等 |
| support / training_lead / training_manager | 管理端 | 查看本部门学员的训练记录、录音、评分结果 |
| operations / ops / operator / sre | 管理端 | 查看全局记录，执行重试、重评等运维操作 |

## 4. 核心使用场景

当前已跑通的主流程：

```
训练单元列表
  → 做题训练
  → 商务技巧文章阅读
  → 商务技巧考卷
  → 录音上传（COS/OSS 浏览器直传优先）
  → ASR 转写（DashScope Paraformer）
  → Deucate / OpenAI-compatible 端点评分
  → 结果页
```

学员端首页形态：从旧 17 关纵向闯关改造为「三模块自选」卡片，分别为：
- PPT 讲解录音
- 商务技巧
- 电梯演讲

对应路径 key：
- `newcomer_training_path_v1`
- `new_seller_modules_v1`

## 5. 当前系统解决的问题

- 为销售新人提供可自助完成的异步训练入口，降低培训人力投入。
- 将「录音训练 + AI 评分」流程产品化，支持浏览器直传、自动转写、结构化评分。
- 为运营/培训管理人员提供内容配置中心，支持训练单元、考卷、文章、评分标准的 CRUD 与发布/归档/回滚。
- 建立权限分层，使内容管理、部门级查看、全局运维三类角色各负其责。
- 通过操作日志、训练记录、评分结果等数据沉淀，支撑培训效果回溯。

## 6. 当前系统不解决的问题

| 类别 | 说明 |
|---|---|
| 实时语音对练 | 模块 4「实时对练」未开发，仅作 disabled / coming-soon 占位；系统不创建、不调用 `sales_bot` 实时 WebSocket 对练 |
| 真正可重算的评分重评 | 当前重评为 append-only 记录，未必真正重新计算分数（待确认/改进） |
| 大规模列表性能 | 多处列表缺少分页，多个 JSONB 列缺少 GIN 索引，存在潜在性能瓶颈 |
| 学员端入口整合 | 后台「学员录音 / 评分结果 / 训练记录」等入口尚未合并统一 |
| 生产级供应商联调 | DashScope / Deucate / StepFun 等真实供应商需补齐部署环境配置后方可稳定联调 |

## 7. 当前产品阶段

**判断：基础闭环已跑通并运营可用，正处于向「可规模化运营 / 可售卖」过渡的第二阶段。**

- **P0 / P1 基础闭环**：已实现并运营可用。
- **第二阶段进行中**：销售训练材料库、考卷/文章绑定、新人训练路径配置中心、商务技巧 AI Coach Chatbot。
- **尚未达到**：稳定可卖、全面生产就绪。

**主要依据**：
- 学员端核心学习-测评-录音-评分链路已落地。
- 管理端内容生产、发布、权限、日志等基础能力已具备。
- 但仍存在实时对练缺位、重评机制不完整、列表缺分页、索引缺失、后台入口未合并等工程与体验债务。
- 真实供应商生产联调与部署环境配置仍需补齐。

# 二、系统整体模块地图

> 本章基于当前代码与契约整理，状态判断相对保守。标注「缺失信息」表示共享事实中未提供足够细节；标注「待确认」表示需与当前实现再次核对。

## 1. 首页 / Dashboard

- **模块名称**：学员端首页（新人训练路径入口）
- **面向的用户**：新入职销售学员（learner）
- **解决的问题**：替代旧 17 关纵向闯关，让学员按「三模块自选」方式进入训练；展示当前可用模块、完成进度和下一步行动。
- **当前实现状态**：**已实现并改造完成**。旧纵向闯关已替换为「PPT 讲解录音、商务技巧、电梯演讲」三卡片自选布局；`realtime_roleplay_placeholder` 作为占位模块默认 disabled。
- **入口页面**：
  - 学员端：`/sales-trainer`（`web/src/app/(dashboard)/sales-trainer/page.tsx`）
- **后端接口或核心服务**：
  - `GET /api/v1/sales-trainer/paths`（learner 路径聚合，返回 `SalesTrainerPath`）
  - `path_config_service.py`、`path_projection_payloads.py`、`path_progress_service.py`
- **依赖配置**：
  - `newcomer_training_path_v1` 路径配置（默认）；历史 `new_seller_modules_v1` 作为兼容 alias
  - 各模块 active revision、单元发布状态、材料/文章/考卷绑定
- **当前体验问题**：
  - 若路径配置缺失，首页返回空路径与 `[NEWCOMER_PATH_CONFIG_MISSING]` 诊断，需管理员预先配置
  - 旧 `Unit.config.path` 仍作为兼容兜底，存在新旧配置不一致的潜在风险
  - 实时对练模块仅展示 disabled/coming-soon 占位
- **未来可能发展方向**：
  - 增加模块完成度可视化、最近学习记录快捷入口
  - 接入实时对练后，将占位模块替换为真实入口

## 2. 新人训练路径

- **模块名称**：Newcomer Training Path（新人训练路径）
- **面向的用户**：学员、内容管理员、培训负责人
- **解决的问题**：把新人入职后的异步学习、录音上传、AI 转写、AI 评分、文章学习和考卷考试路径结构化；提供统一的模块编排、版本治理和完成规则。
- **当前实现状态**：**已实现**。支持路径级 revision 治理（`AssetRevision` + `AssetActiveRevision`），默认 `path_key = newcomer_training_path_v1`。
- **入口页面**：
  - 学员端：`/sales-trainer`
  - 管理端：`/admin/sales-trainer/paths`
- **后端接口或核心服务**：
  - `GET/PUT /api/v1/admin/newcomer-training/path-config`
  - `POST /api/v1/admin/newcomer-training/path-config/publish`
  - `POST /api/v1/admin/newcomer-training/path-config/rollback`
  - `path_config_service.py`、`path_config_operations.py`
- **依赖配置**：
  - 路径配置 DTO（`NewcomerTrainingPathConfig`）
  - 模块配置数组、完成规则、绑定目标单元/文章/考卷/材料组
- **当前体验问题**：
  - 历史 `new_seller_modules_v1` 与 `newcomer_training_path_v1` 双 key 并存，需维护兼容逻辑
  - 配置非法时返回 `[NEWCOMER_MODULE_CONFIG_INVALID]`，但对管理员的修复引导依赖日志与错误码文本
- **未来可能发展方向**：
  - 支持多条训练路径（如针对渠道销售、KA 销售的不同路径）
  - 路径完成状态与 HR/绩效系统打通

## 3. 训练模式

- **模块名称**：训练单元执行模式（quiz / audio_scoring）
- **面向的用户**：学员
- **解决的问题**：把「做题训练」和「录音演练」两类核心训练形态封装为可配置单元，供路径模块引用。
- **当前实现状态**：**已实现**。`unit_type` 仅支持 `quiz` 和 `audio_scoring`；单元级 revision 治理已落地。
- **入口页面**：
  - 做题：`/sales-trainer/quiz/[unitId]`、`/sales-trainer/quiz/result/[attemptId]`
  - 录音：`/sales-trainer/audio/[unitId]`、`/sales-trainer/audio/result/[submissionId]`
  - 学习 hub：`/sales-trainer/learn/hub`、`/sales-trainer/learn/[unitId]`
- **后端接口或核心服务**：
  - `GET /api/v1/sales-trainer/units`、`GET /api/v1/sales-trainer/units/{unit_id}`
  - `GET /api/v1/sales-trainer/units/{unit_id}/brief`
  - `POST /api/v1/sales-trainer/quiz-attempts`、`POST /api/v1/sales-trainer/audio-submissions`
  - `unit_service.py`、`unit_revision_service.py`、`quiz_service.py`、`audio_submission_service.py`
- **依赖配置**：
  - 训练单元配置（`SalesTrainerUnit.config` JSONB）
  - 题目绑定、评分提示词、材料绑定、通过线
- **当前体验问题**：
  - 单元配置依赖多个 JSONB 字段，缺少 GIN 索引可能导致大数据量下查询变慢（属于已知风险）
  - 录音上传优先走 COS/OSS 浏览器直传，本地/fallback multipart 路径在对象存储不可用时兜底
- **未来可能发展方向**：
  - 增加更多 `unit_type`（如视频演练、文档阅读打卡）
  - 单元级前置依赖（必须完成 A 才能解锁 B）

## 4. 商务技巧模块

- **模块名称**：商务技巧（Business Skills）
- **面向的用户**：学员、内容管理员
- **解决的问题**：让学员通过「文章学习 + 考卷考试 + AI Coach 对话训练」掌握商务沟通技巧。
- **当前实现状态**：**部分实现/改造中**。文章学习和考卷考试已落地；AI Coach Chatbot 已开发并进入配置阶段。
- **入口页面**：
  - 学员端：`/sales-trainer/business-skills`、`/sales-trainer/business-skills/exam`、`/sales-trainer/business-skills/coach`
  - 管理端：`/admin/sales-trainer/articles`、`/admin/sales-trainer/papers`、`/admin/sales-trainer/ai-coach`
- **后端接口或核心服务**：
  - `GET /api/v1/newcomer-training/modules/{module_key}/article`
  - `GET/POST /api/v1/newcomer-training/papers/{paper_id}`、`POST /api/v1/newcomer-training/paper-attempts`
  - `POST /api/v1/newcomer-training/ai-coach/chat/sessions`、message/event 接口
  - `article_exam_prerequisite_service.py`、`exam_paper_service.py`、`ai_coach_chat_service.py`
- **依赖配置**：
  - 模块配置中 `module_type="article_exam"`，`learning_content_id` 与 `exam_paper_id` 绑定
  - AI Coach 配置（`modules[].ai_coach`）
  - 全局 LLM（DashScope/StepFun）、Prompt Template
- **当前体验问题**：
  - 考试提交前必须完成文章阅读，未完成时返回 `[NEWCOMER_ARTICLE_PROGRESS_REQUIRED]`，但前端阅读进度持久化方式待确认
  - AI Coach 依赖 prompt 工程与全局 LLM，输出稳定性受模型和温度参数影响
  - 简答题 AI 批改在模型不可用时仅保存答案、返回 `score=null`
- **未来可能发展方向**：
  - 商务技巧文章支持富媒体、案例视频
  - AI Coach 扩展多轮场景剧本和角色扮演

- **解决的问题**：为商务技巧等模块提供可版本治理的阅读材料，作为考试前置输入。
- **当前实现状态**：**已实现**。通过 `GET /api/v1/newcomer-training/modules/{module_key}/article` 暴露；底层复用现有 `LearningContent` / `LearningChapter`。
- **入口页面**：
  - 学员端：`/sales-trainer/business-skills`
  - 管理端：`/admin/sales-trainer/articles`
- **后端接口或核心服务**：
  - `GET /api/v1/newcomer-training/modules/{module_key}/article`
  - `article_binding_service.py`
- **依赖配置**：
  - 模块配置 `learning_content_id`
  - `LearningContent` / `LearningChapter` 发布状态
- **当前体验问题**：
  - 文章内容、章节、图片 Markdown 仍由现有后台维护，与销售训练模块的绑定关系在路径配置中管理
  - 文章阅读进度是否被持久化并用于考试门禁，共享事实中未明确说明
- **未来可能发展方向**：

## 6. 练习题 / Quiz

- **模块名称**：练习题（Quiz）
- **面向的用户**：学员、内容管理员
- **解决的问题**：支持单选、多选、判断、简答四类题型的自动/人工评分，作为训练单元和考卷的底层执行能力。
- **当前实现状态**：**已实现**。销售训练专属题库已独立；自动判分覆盖单选/多选/判断；简答题保存答案，是否 AI 批改由配置决定。
- **入口页面**：
  - 学员端：`/sales-trainer/quiz/[unitId]`、`/sales-trainer/quiz/result/[attemptId]`
  - 管理端：`/admin/sales-trainer/questions`、`/admin/sales-trainer/questions/categories`
- **后端接口或核心服务**：
  - `POST /api/v1/sales-trainer/quiz-attempts`、`GET /api/v1/sales-trainer/quiz-attempts/{attempt_id}`
  - `quiz_service.py`、`question_service.py`、`question_bank_adapter.py`
- **依赖配置**：
  - `question_items` / `question_categories` 表 `usage_scope = sales_trainer`
  - 训练单元 `quiz.enabled_question_types`、`shuffle_questions`
- **当前体验问题**：
  - 若题目声明为单选/多选/判断但缺少必要选项结构，后台创建/发布会阻断并记录 `question_type_unsupported`
  - 简答题复杂 AI 批改能力较弱，本阶段不重点扩展
- **未来可能发展方向**：
  - 增加题目难度标签、知识点标签
  - 简答题 AI 批改与采分点引擎

## 7. 考试 / 测评

- **模块名称**：考卷管理（Exam Paper）
- **面向的用户**：学员、内容管理员、培训负责人
- **解决的问题**：把商务技巧等模块的考试从通用 quiz 单元中抽离为独立一等对象，支持独立发布、版本治理和历史记录冻结。
- **当前实现状态**：**已实现**。`ExamPaper` 为独立表，支持 working/published/archived revision；考试结果页冻结 `paper_revision_id` 与路径上下文。
- **入口页面**：
  - 学员端：`/sales-trainer/business-skills/exam`
  - 管理端：`/admin/sales-trainer/papers`
- **后端接口或核心服务**：
  - `GET /api/v1/sales-trainer/papers/{paper_id}`、`POST /api/v1/sales-trainer/paper-attempts`
  - `exam_paper_service.py`、`exam_paper_publish_workflow.py`、`paper_snapshot_attempt_service.py`
- **依赖配置**：
  - 考卷 `module_key`、`unit_id` 绑定
  - `pass_threshold`、题目引用 `QuestionItem`
- **当前体验问题**：
  - 考卷底层仍绑定一个兼容 `quiz` 执行单元，管理员需同时维护 paper 与 unit 的关系
  - 历史 attempt 展示依赖 answer payload 内的题目快照，若快照缺失可能展示异常
- **未来可能发展方向**：
  - 考卷与训练单元完全解耦
  - 支持补考策略、考试时间限制

# 三、用户角色与使用路径

## 1. 销售新人

### 进入系统后看到什么
- 学员端首页呈现为「三模块自选」卡片，模块名称为：
  - **PPT 讲解录音**
  - **商务技巧**
  - **电梯演讲**
- 对应路径 key：`newcomer_training_path_v1` / `new_seller_modules_v1`
- 旧版 17 关纵向闯关入口已下线或改造为上述入口。

### 如何开始训练
- 在首页点击对应模块卡片进入训练单元列表。
- 选择当前需要完成的训练单元，进入学习、做题或录音任务。
- **缺失信息**：新人是否有必须按顺序解锁的约束、首次登录引导流程、未完成任务提醒机制，目前未明确。

### 如何学习内容
- 在「商务技巧」模块中，阅读管理端配置的销售训练材料库文章。
- 材料版本控制通过 `Material` / `MaterialVersion` 实现，当前新人看到的是已发布的当前版本。
- **缺失信息**：是否支持视频、PPT、PDF 等多媒体学习材料；学习进度是否实时保存，未明确。

### 如何做题
- 进入训练单元中的「做题训练」。
- 题目来源于销售训练专属题库。
- 答题后产生 `QuizAttempt` 记录。
- **缺失信息**：题目类型、是否有倒计时、是否支持多次作答、错题解析展示方式，目前未明确。

### 如何考试
- 进入商务技巧考卷完成考试。
- 考卷通过 `ExamPaper` 模型管理，由管理端配置并发布。
- 考试结果会记录到 `QuizAttempt` 或相关训练记录中。
- **缺失信息**：考试及格线、是否允许重考、考试与训练的触发条件，目前未明确。

### 如何获得反馈
- 录音任务：完成录音后上传（COS/OSS 浏览器直传优先）→ ASR 转写（DashScope Paraformer）→ AI 评分（Deucate / OpenAI-compatible）→ 展示评分结果页。
- 核心流程涉及：`AudioSubmission` → `Transcript` → `ScoreResult`。
- 做题/考卷反馈：通过训练单元结果与 `QuizAttempt` 展示。
- **缺失信息**：反馈详情页是否展示逐条评分维度、标准答案对比、改进建议，目前未明确。

### 如何知道自己进步了
- 可查看个人训练记录与历史评分结果（对应 `TrainingRecord` / `ScoreResult`）。
- **缺失信息**：学员端是否提供进度条、能力雷达图、历史趋势图、排行榜、完成率等可视化成长指标，目前未明确。

## 2. 销售主管 / 培训负责人

### 如何查看训练情况
- 通过管理端「学员录音 / 评分结果 / 训练记录」入口查看所辖团队数据。
- 权限角色：`support` / `training_lead` / `training_manager`，范围限制为**本部门**记录。
- 涉及数据实体：`AudioSubmission`、`Transcript`、`ScoreResult`、`TrainingRecord`。
- **注意**：目前后台入口「学员录音 / 评分结果 / 训练记录」尚未合并为一个统一入口，存在体验割裂风险。

### 如何配置训练内容
- 训练单元、题库、考卷、材料库等配置主要由 `admin` / `super_admin` / `content_admin` / `newcomer_content_admin` 负责。
- 销售主管 / 培训负责人是否拥有直接配置权限，**缺失信息**；当前权限矩阵中主管角色主要定位在「查看本部门记录」，未明确赋予内容发布权限。

### 如何判断新人是否合格
- 依赖考卷得分与录音 AI 评分结果。
- **缺失信息**：系统是否提供统一的「合格 / 不合格」判定规则、结业标准、自动结业/晋升能力，目前未明确。

### 如何发现薄弱点
- 通过 `ScoreResult` 查看 AI 评分维度与得分分布。
- 通过 `TrainingRecord` 追踪完成率、重试次数、录音提交情况。
- 通过 `AudioSubmission` 与 `Transcript` 回溯录音内容与转写文本。
- **缺失信息**：是否自动聚合同一学员/团队的薄弱维度并生成推荐训练计划，目前未明确。

### 如何推动团队训练
- 可基于训练记录督促未完成新人补做任务。
- **缺失信息**：是否支持主管下发训练任务、设置截止时间、发送催办通知、导出团队报表等功能，目前未明确。

## 3. 管理员 / 运营人员

### 管理哪些配置
- **训练单元**：`SalesTrainerUnit`，支持 `quiz` / `audio_scoring` 两种类型，提供 CRUD + 发布 / 归档 / 回滚。
- **题库**：销售训练专属题库。
- **考卷**：`ExamPaper`，包括考卷管理。
- **材料库**：`Material` / `MaterialVersion`，销售训练材料库。
- **录音评分标准**：`ScoreResult` 背后的评分规则配置。

# 四、当前核心业务闭环

## 1. 闭环总览

当前系统围绕「新人训练路径」形成了一条**可运营的异步训练主线**，整体流程可概括为：

```
配置训练路径 → 学员进入新人训练路径 → 选择学习模块 → 完成练习/考卷 → 提交录音 → 转写与 AI 评分 → 查看结果 → 管理端查看训练记录/评分 → 运营人员调整路径与内容
```

但示例流程中提到的「进入 AI 教练训练局 → 获取反馈和总结 → 根据数据调整训练内容和策略」仅部分落地，**实时对练环节完全未接入**。

| **真实供应商联调** | 依赖部署环境补齐 | DashScope、Deucate、COS/OSS 等外部依赖的完整生产联调需部署环境配置到位 |

|---|---|---|

| **全模块 AI Coach** | 未覆盖 | PPT 讲解、电梯演讲等模块尚无专属 AI 教练流程 |
| **自动化的训练策略调整** | 未实现 | 管理端可人工调整路径与内容，但「根据数据自动推荐训练策略/弱项补强」的能力缺失 |
| **重评结果的一致性感知** | 未闭环 | 若重评未真正重算，则学员侧与管理端对分数的认知可能不一致 |

## 5. 最影响产品价值的环节

按对产品价值的潜在影响排序：

1. **实时对练未接入（影响最大）**
   - 销售训练的核心价值之一是「模拟真实对话、即时反馈」；当前仅支持异步录音提交，无法提供实时互动体验。
   - 模块 4 的占位状态直接影响产品竞争力和用户完成率。

2. **重评可能只记录未真正重算（信任风险）**
   - 若运营人员点击重评后分数未更新，将直接损害管理端数据可信度，并可能导致对学员能力的误判。

3. **AI Coach 覆盖范围过窄**
   - 当前仅商务技巧有 AI Coach，PPT 讲解、电梯演讲等高频场景仍依赖静态材料与录音，智能化辅导价值未充分发挥。

4. **后台入口未合并 + 列表缺分页/索引**
   - 影响运营效率与系统可扩展性，属于「当前可用、长期拖累」的结构性问题。

5. **材料版本追溯刚上线**
   - 存在运营误操作覆盖内容、版本绑定不一致的潜在风险，需通过实际使用验证。

## 6. 关键风险提示

- **实时对练是明确禁区，也是明显缺口**：当前架构下 `sales_trainer` 不触碰 `sales_bot` 的 WebSocket 实时对练，产品侧需通过其他方式（如更完善的异步 AI Coach）弥补体验缺口。
- **评分可信度依赖重评链路完整性**：在重评真正调用 Deucate 并重写 `ScoreResult` 之前，管理端应谨慎将评分数据用于考核决策。
- **AI Coach 效果依赖 prompt 与 LLM 稳定性**：DashScope/StepFun 的响应质量、延迟和成本会直接决定商务技巧 AI Coach 的用户体验。
- **材料版本化需要运营 SOP 配合**：技术能力已具备，但若缺乏「发布/归档/回滚」的运营规范，仍可能出现内容版本与训练路径绑定不一致的问题。

# 五、训练体系设计

## 1. 训练体系总览

本系统面向**企业新人销售**的异步训练场景，当前阶段以「知识输入 + 题目练习 + 录音实操 + 考卷测评 + AI 教练辅助」为核心闭环，暂不支持实时对练。

| 维度 | 当前设计 |
|------|----------|
| **训练目标** | 帮助新人销售掌握产品讲解、商务技巧与电梯演讲能力，通过可量化的录音评分与考卷测评完成上岗前训练。 |
| **训练对象** | 新入职销售人员（新人），由 `newcomer`、`new_seller` 等角色进入学员端。 |
| **训练内容组织** | 学员端首页采用「三模块自选」卡片结构：**PPT 讲解录音、商务技巧、电梯演讲**。内容由管理端通过训练单元、材料库、考卷、录音评分标准分别配置。 |
| **训练路径设计** | 路径 key 为 `newcomer_training_path_v1` / `new_seller_modules_v1`，已从旧版 17 关纵向闯关改造为模块自选结构。路径内部具体依赖关系、完成顺序、解锁规则：**缺失信息/待确认**。 |
| **从“完成任务”到“能力提升”** | 当前主要通过 **训练记录、评分结果、QuizAttempt、AudioSubmission** 沉淀学习数据，但尚未形成明确的能力画像或成长曲线看板；能力归因与个性化推荐机制**缺失信息/未开发**。 |

## 4. 主要体验问题与风险

1. **实时对练缺失**：情境演练能力空白，当前为 coming-soon 占位，影响「沉浸式训练」体验。
2. **能力画像未形成**：大量评分与做题数据未转化为可视化的能力成长视图。
3. **重评逻辑存疑**：重评操作 append-only 记录，未必真正重算分数，可能导致管理者看到重复或陈旧结果。
4. **错题复习机制未明确**：缺乏基于错题的复习推送，影响训练闭环。
5. **分页与索引问题**：列表缺少分页、多个 JSONB 列缺 GIN 索引，随着数据增长可能影响管理端查询性能。
6. **AI Coach 效果依赖模型**： coaching 质量依赖全局 LLM 与 prompt，缺乏独立的评估与调优闭环。

## 5. 下一步建议（基于当前事实）

1. **补齐训练路径的依赖与解锁规则**，明确 `newcomer_training_path_v1` 下模块完成顺序。
2. **明确考卷合格标准**（分数线、重考次数、通过有效期）。
3. **验证并完善重评逻辑**，确保重评真正触发评分重算并更新结果。
4. **设计错题复习与薄弱点推送**，盘活 `QuizAttempt` 与 `ScoreResult` 数据。
5. **建设学员能力画像看板**，将训练记录聚合为可视化成长曲线。
6. **在实时对练模块启动前**，先明确其技术方案与 `sales_bot` 的边界，避免模块职责混淆。

## 14. 总体评估与下一步建议

### 14.1 已配置化较好的部分
- 训练单元、考卷、材料、题库、录音评分标准、AI Coach（`business_skills`）已有独立后台入口。
- 训练单元/考卷/材料依托 `AssetRevision` 实现版本化与回滚，具备较强的内容治理能力。
- `OperationLog` 为配置变更提供审计基础。

### 14.2 当前主要缺口
1. **流程类规则未配置化**：自动推进规则、补救规则、重试/重评逻辑目前缺失统一后台入口，高度依赖硬编码。
2. **文案模板未统一**：前端仍存在硬编码文案，运营无法自助调整。
3. **路径与模块顺序的驱动关系待确认**：需验证「新人训练路径配置中心」是否真正驱动学员端首页渲染，还是前端仍写死三模块顺序。
4. **权限配置可视化待补齐**：权限矩阵已知，但是否有后台界面动态调整角色-数据范围映射待确认。
5. **榜单规则缺失信息**：当前事实未提及榜单，若未来需要则属于新增配置域。
6. **技术债影响配置查询**：多个 JSONB 列缺 GIN 索引、列表缺分页，会限制后台按动态条件检索配置/记录的能力。

### 14.3 建议下一步
- 将自动推进规则、补救规则、文案模板纳入配置中心，形成独立的配置表与版本管理。
- 明确训练路径配置中心与前端渲染的契约，确保首页模块顺序、标题、图标均可由后端配置驱动。
- 对重评逻辑进行契约修复：明确 append-only 记录与真实重算分数的语义，避免把「再评一次」简单做成「再记一次」。
- 为高频查询的 JSONB 列补充 GIN 索引，并统一后台列表分页规范。
- 将「学员录音/评分结果/训练记录」合并为统一的训练记录中心，并支持可配置的展示字段与导出模板。

## 汇总

- **已落库且可展示**：学习进度、练习记录、考试记录、AI 教练会话记录、训练单元/材料/考卷/评分结果等原子数据。
- **已落库但未充分聚合展示**：团队完成率、模块通过率、路径完成情况、内容质量、AI 教练生成质量。
- **计划中/待建设**：连续训练、掌握度雷达、薄弱点自动归纳、复习计划、难度变化、高风险学员识别。
- **当前缺失**：激活率、留存率、管理端使用率、客户可感知价值指标等商业效果指标。

## 风险与下一步建议

1. **指标口径不统一**：「完成率」在学员端、管理端、路径配置中心可能口径不同，建议统一完成定义。
2. **重评数据真实性问题**：共享事实提到「重评目前 append-only 记录但未必真正重算分数」，会影响能力成长数据的准确性。
3. **缺少分层看板**：当前数据原子记录丰富，但面向学员、管理者、运营/决策者的聚合指标不足。
4. **商业价值指标依赖外部系统**：需与客户 HR、CRM、成单数据打通，当前未在 `sales_trainer` 域内建设。

## 1. 按优先级整理

### P0 — 不做会影响基本可用

1. **重评真正重算分数**
   - 当前：重评 append-only 记录，但未必真正重算分数。
   - 风险：运营点击「重评」后结果不可信，影响培训考核公正性。

   - 当前：多个 JSONB 列缺 GIN 索引。
   - 风险：随着配置中心、评分结果等数据增长，查询性能急剧下降，可能导致后台页面卡顿。
   - 建议：梳理高频 JSONB 查询字段，分批补索引。

3. **后台入口合并**
   - 当前：「学员录音/评分结果/训练记录」三个后台入口尚未合并。
   - 风险：运营需要在多个页面跳转，易漏看数据，影响问题排查效率。
   - 建议：统一为「学员训练档案」单一入口，按权限聚合。

4. **列表分页**
   - 当前：多个列表缺分页。
   - 风险：数据量增大后页面加载失败或超时。
   - 建议：核心列表（训练单元、考卷、学员记录、操作日志）补齐分页。

   - 风险：学员不知道「哪里说得不好」，训练效果打折。
   - 建议：结合评分维度输出具体话术改进建议。

   - 当前：依赖全局 LLM 与 prompt 工程，幻觉与上下文管理待优化。
   - 风险：AI Coach 回答偏离销售场景，学员不信任。
   - 建议：增加领域知识库约束、会话上下文截断策略、输出校验。

## 2. 按风险类别整理

### 产品风险

- **实时对练长期占位**：模块 4 仅 coming-soon，影响产品完整性与用户信任。
- **后台入口割裂**：「学员录音/评分结果/训练记录」未合并，运营效率低。
- **重评语义不清**：用户可能误以为重评就是重新算分，实际未必，存在信任危机。
- **P0/P1 基础功能边界外溢**：销售训练模块被禁止创建/调用 sales_bot 实时对练，需严防需求方绕过边界。

### 技术风险

- **JSONB 缺 GIN 索引**：数据量增长后查询性能恶化。
- **列表缺分页**：大数据量下接口超时/前端卡死。
- **异步任务可靠性待确认**：转写/评分任务队列的死信、重试、幂等性未明确。
- **多环境配置缺失**：真实供应商联调未在生产-like 环境完成。
- **缓存与连接池策略待确认**：Redis/PostgreSQL 高可用配置缺失信息。

### AI 质量风险

- **评分可解释性不足**：Deucate 输出维度分数，但学员难以理解如何改进。
- **重评不重算**：评分结果权威性受损。
- **AI Coach 幻觉与上下文管理**：依赖全局 LLM，领域约束不足。
- **ASR 准确率**：方言、专业术语、音频质量影响转写质量，进而影响评分。

### 训练效果风险

- **学习路径缺乏依赖与进度可视化**：学员可能跳过关键训练。
- **错题/薄弱点分析缺失**：无法针对性提升。
- **评分标准未校准**：不同批次评分尺度不一致，影响培训公平性。
- **没有人工复核闭环**：评分异常时缺乏申诉与专家复核通道。

### 后台治理风险

- **配置变更无版本化/审批**：误操作影响线上。
- **操作日志保留与导出策略缺失**：审计合规风险。
- **权限矩阵执行细节未逐条验证**：存在越权或权限过宽可能。
- **数据归档策略缺失**：长期存储与查询性能风险。

### 商业化风险

- **实时对练缺失影响售前演示**：企业客户期望「AI 实时对练」能力。
- **训练效果数据不足**：难以向客户证明 ROI。
- **供应商依赖**：DashScope/Deucate/StepFun 的稳定性与成本需持续评估。
- **多租户/部门隔离**：当前权限矩阵按角色划分，若未来拓展大客户，租户隔离能力待确认。

# 十、给 ChatGPT Pro 的项目上下文摘要

## 这是什么样的项目

这是一个面向企业销售新人培训的 **AI 驱动异步训练系统**，用户侧产品名为「新人训练路径」，内部技术代号仍保留 `sales_trainer`。系统不是通用学习管理系统（LMS），而是聚焦销售场景下的「学—练—测—评」闭环：学员通过三模块自选卡片（PPT 讲解录音、商务技巧、电梯演讲）进入训练，完成文章阅读、考卷答题、录音上传，后台自动完成 ASR 转写与 AI 评分，最终形成训练记录供管理者查看。

系统的技术栈为 Python/FastAPI + Next.js/React，依赖 PostgreSQL、Redis、ChromaDB，外部服务包括 DashScope（ASR/LLM）、Deucate/OpenAI-compatible 端点（评分）、腾讯云 COS/阿里云 OSS（文件存储）。它与企业已有的实时语音对练系统（`sales_bot`）在架构上被**明确切割**：`sales_trainer` 只做异步训练，禁止创建或调用实时 WebSocket 对练会话。

## 项目现在走到哪一步

**P0/P1 基础闭环已经完成并运营可用。** 这意味着：学员可以登录、看到三模块首页、完成做题/文章/考卷/录音训练、拿到 AI 评分结果；管理员可以在后台创建训练单元、管理销售训练专属题库、发布考卷、上传材料版本、配置录音评分标准、查看学员录音/评分结果/训练记录、查看操作日志和配置健康。

**当前正处于第二阶段（进行中）**，核心工作包括四块：
1. **销售训练材料库**：把 PPT、逐字稿、示例录音等作为一等对象管理，支持版本发布与提交时快照冻结。
2. **考卷与文章绑定**：把商务技巧的「先读后考」做成独立一等对象，支持考卷 revision 治理。
3. **新人训练路径配置中心**：用后端配置驱动学员端首页的三模块展示，支持发布/回滚。
4. **商务技巧 AI Coach Chatbot**：在商务技巧模块内提供对话式 AI 教练，自动出题、评分、解释、总结。

从数据模型看，核心表已经覆盖：训练单元（`SalesTrainerUnit`）、考卷（`ExamPaper`）、材料与版本（`Material`/`MaterialVersion`）、录音提交与转写评分（`AudioSubmission`/`Transcript`/`ScoreResult`）、做题记录（`QuizAttempt`）、资产修订（`AssetRevision`）、AI 教练会话（`AiCoachChatSession`/`Message`/`UiEvent`/`CoachAction`）、训练记录（`TrainingRecord`）和操作日志（`OperationLog`）。

但系统**还没有达到稳定可卖阶段**。实时对练模块是占位状态；重评逻辑可能只是 append-only 记录而未必真正重算分数；多个列表缺少分页、多个 JSONB 字段缺少 GIN 索引；后台「学员录音/评分结果/训练记录」三个入口尚未合并；真实供应商（DashScope/Deucate）的生产联调仍需部署环境补齐配置。

## 系统骨架：三条主线

**第一条主线是学员学习闭环。** 学员进入 `/sales-trainer` 首页，看到 PPT 讲解录音、商务技巧、电梯演讲三模块。PPT 和电梯演讲走 `audio_scoring` 单元：下载/查看材料 → 上传录音 → 后端转写 → Deucate 评分 → 结果页。商务技巧走 `article_exam` 模块：先读文章 → 再考商务技巧考卷 →  optionally 进入 AI Coach Chatbot 继续练。所有结果都会沉淀为训练记录。

**第二条主线是管理端内容生产闭环。** 管理员在 `/admin/sales-trainer` 工作台进入各子模块：训练单元、题库、考卷、材料库、录音评分标准、路径配置、AI Coach 配置。关键内容对象（单元、考卷、材料）都支持 `draft → published → archived` 生命周期和版本回滚。发布后的变更只影响之后进入训练的学员，历史提交通过快照冻结保证可追溯。

**第三条主线是运营/运维监控闭环。** 培训负责人按 `department` 查看本部门记录；运维人员查看全局记录、重试失败的转写/评分任务、执行历史重评。配置健康页展示存储、ASR、Deucate、上传限制等状态，但只读且不暴露密钥。

## AI 教练在整个系统中的位置

AI 教练当前**只嵌入在商务技巧模块**中，形态是对话式 Chatbot，而不是实时语音对练。它位于「考卷测评」之后，作为「继续练」的补充入口：学员考完试或直接进入 `/sales-trainer/business-skills/coach`，与 AI 进行多轮交互，系统根据学员答案自动推进（继续、加难、补救、换场景、总结、结束）。

AI 教练的配置在 `/admin/sales-trainer/ai-coach`，可以调整启用状态、允许题型、连续答对/答错阈值、补救策略、Prompt 绑定等。它的输出通过白名单 `ui_event` 卡片（`quiz_card`、`explanation_card`、`summary_card`、`followup_prompt`）渲染到前端，前端不执行 LLM 返回的任意 JSX/HTML/脚本。

AI 教练的当前价值是**把「考完即止」延伸为「考后继续练」**，让商务技巧训练从一次性考试变成可重复的对话练习。但它的效果高度依赖全局 LLM（DashScope/StepFun）与 prompt 工程，目前只覆盖商务技巧，PPT 讲解和电梯演讲还没有 AI 教练入口。实时对练模块仍处于占位状态，因此 AI 教练是当前最接近「互动训练」的能力，但不能替代真正的实时语音对练。

## 已经验证什么、还没验证什么

**已验证**：
- 学员端三模块首页可渲染。
- 做题提交、考卷提交、文章阅读前置校验可跑通。
- 录音上传（含 COS/OSS 浏览器直传）、转写、Deucate 评分端到端 smoke 已在本地方便环境跑通。
- 后台训练单元/考卷/材料的 CRUD、发布、归档、回滚可用。
- 操作日志、训练记录、配置健康页面可查看。
- 前后端测试覆盖核心流程。

**尚未验证/待补齐**：
- 生产环境真实供应商（DashScope/Deucate/StepFun）的稳定联调。
- 重评操作是否真正重新计算分数并更新学员可见结果。
- AI Coach Chatbot 在真实业务材料上的输出质量与稳定性。
- 大训练记录量下的列表性能（缺分页、缺 GIN 索引）。
- 多部门、多角色权限边界的端到端审计。
- 学员端能力画像、成长曲线、排行榜等数据产品的有效性。

## 当前最值得讨论的问题

把这份上下文交给 ChatGPT Pro 后，建议优先围绕以下五个问题展开深度分析：

1. **产品阶段判断：当前更应该补齐「可卖」的临门一脚，还是继续扩展功能？**
   实时对练占位、重评不重算、后台入口割裂等问题说明系统还没达到可稳定售卖的状态。但 AI Coach、材料库、考卷等新功能仍在快速开发。需要判断：是先收敛工程债务（分页、索引、重评语义、入口合并）再卖，还是边扩展边修复。

2. **实时对练缺位的产品替代策略是什么？**
   架构上 `sales_trainer` 禁止调用 `sales_bot` 实时对练，但企业客户大概率会把「AI 实时对练」当作核心卖点。没有实时对练，系统如何证明价值？是靠更完善的异步 AI Coach、更细的录音反馈、还是未来通过独立契约与启用开关接入实时对练？

3. **AI Coach 的边界与扩展节奏。**
   当前 AI Coach 仅覆盖商务技巧，且依赖全局 LLM。是否应该扩展到 PPT 讲解、电梯演讲？如果扩展，是复用同一套 Chatbot 框架还是为每个模块独立配置？如何建立 AI Coach 的效果评估闭环（而不仅是功能可用）？

4. **数据如何转化为「能力成长」而非「任务完成」。**
   系统已经积累了大量原子数据（做题、录音、评分、AI 教练会话），但还没有形成能力画像、薄弱点分析、个性化推荐。下一步应该把重点放在哪一层：数据聚合与指标口径统一、学员端成长视图、还是管理者端的团队诊断与干预工具？

5. **重评与评分的可信度治理。**
   如果重评只是 append-only 记录而不真正重算分数，那么管理端基于评分结果做决策就存在信任风险。需要明确：重评的契约是什么？什么情况下允许覆盖历史分数？如何保证学员侧与管理端对分数的认知一致？这是否会阻塞把系统用于正式考核场景？

这五个问题相互关联：实时对练决定产品上限，AI Coach 决定当前差异化，数据/画像决定长期价值，重评可信度决定能否进入考核场景，工程债务决定能否稳定规模化。建议 ChatGPT Pro 从这五个交叉点切入，帮助判断下一步的最小可行产品化路径。
