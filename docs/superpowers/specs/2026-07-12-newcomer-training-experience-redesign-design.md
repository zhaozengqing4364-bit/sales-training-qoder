# 新人训练任务化体验重设计

> **状态：Superseded / Legacy 历史记录（2026-07-16）。** 本文只解释当前在途 UI 的形成过程，不再作为目标领域、页面或验收权威；Foundation target 见 [`../../newcomer-foundation-contract-index.md`](../../newcomer-foundation-contract-index.md)。

## 背景

现有系统已经具备活动编排、不可变发布修订、资源校验、并发保护和六类活动执行器，架构治理基础是合理的。公网体验的问题不在“能力缺失”，而在信息表达仍以配置结构为中心：学员先看到抽象阶段和巨大进度卡，管理员同时面对大纲、表单、预览、校验和历史，导致主任务不清晰、页面拥挤、内容编排像编辑 JSON Schema。

本设计是对现有《新人训练体验闭环设计》的增量改版，不改变活动编排领域模型，只重构学员展示合同与管理端编排交互。

## 成功标准

### 学员端

- 进入页面 3 秒内知道：现在做什么、为什么做、怎么做、多久做完、怎样算通过。
- 首屏只有一个主操作，抽象阶段名称退居为路径位置提示。
- 手机首屏能看到任务名称、预计用时和主按钮，不被装饰性大卡片占满。
- 活动页统一遵循“目标 → 材料 → 执行 → 反馈”，不展示修订号、版本治理等后台术语。

### 管理端

- 默认只同时处理“大纲定位”和“当前对象编辑”两个任务。
- 预览使用与学员端相同的任务组件，并按需在大抽屉/对话框打开。
- 阶段、模块和活动的学员文案可配置；新增内容无需改代码。
- 高频操作显眼，低频移动、复制、删除操作按悬停或聚焦出现。
- 保存草稿不要求填写理由；发布仍要求说明并保留审计。

## 页面契约

### 学员训练首页

- 目标用户：已报名新人。
- 使用场景：进入训练后决定下一步并开始执行。
- 主任务：完成当前可执行活动。
- 主操作：由活动能力映射出的动词，例如“开始录音讲解”“开始答题”。
- 核心信息：任务目标、价值说明、步骤、预计用时、通过标准、路径位置。
- 数据来源：固定 revision 的 Journey DTO。
- 状态：loading、empty、error、locked、in progress、processing、completed。
- 禁止展示：revision、schema、资源 ID、内部枚举、测试术语。

### 学员活动页

- 目标用户：正在执行某一活动的新人。
- 主任务：依据材料完成活动并得到结果/下一步。
- 主操作：活动执行器的开始/提交动作。
- 核心结构：任务目标、步骤与通过标准；材料；执行器；结果与下一步。
- 降级：材料失败可重试或打开原资源；麦克风失败可上传录音；评分处理中明确告知。

### 管理员路径编排

- 目标用户：培训管理员、内容运营。
- 主任务：定位一个节点，配置学员体验，检查并发布。
- 主操作：保存草稿；发布作为显式高风险操作。
- 核心结构：左侧可折叠大纲；右侧聚焦编辑；顶部操作条；按需真实预览；校验和历史放在次级区域。
- 数据来源：工作修订、资源目录、修订历史。
- 状态：局部资源 loading/error、dirty、saving、validating、conflict、publishing、success。
- 禁止展示：普通编辑流程中的 raw JSON、数据库主键和无解释枚举。

## 信息架构

### 学员端：任务优先

```text
训练路径位置（弱）
  → 当前具体任务（强）
    → 完成后能做到什么
    → 为什么值得做
    → 3～5 个步骤
    → 预计用时 / 通过标准
    → 唯一主按钮
  → 后续路径（折叠、次要）
```

阶段标题可以继续是“入门认知”，但首屏主标题必须来自当前活动或模块目标。默认种子内容改用结果语言，例如“能用 3 分钟讲清公司与方案”，避免“认知、赋能、体系化”等抽象表达占据主视觉。

### 管理端：两栏聚焦

```text
顶部：状态 / 真实预览 / 保存草稿 / 检查 / 发布
左栏：路径大纲、搜索、添加、问题定位
右栏：当前阶段/模块/活动的基础内容与规则
按需浮层：学员真实预览
次级折叠区：校验结果、修订历史、高级规则
```

## 配置合同

保持 `TrainingPathPayload.schema_version = "v1"`，新增字段均可选并有安全默认值，因此历史 revision 不需要迁移：

- `PhaseConfig.outcome: str | None`：完成阶段后能做到什么。
- `ModuleConfig.outcome: str | None`：完成模块后能做到什么。
- `ActivityBase.objective: str | None`：本次具体任务目标。
- `ActivityBase.why_it_matters: str | None`：业务价值说明。
- `ActivityBase.steps: list[str]`：建议 2～5 步。
- `ActivityBase.success_criteria: list[str]`：学员可理解的通过标准。
- `ActivityBase.primary_action_label: str | None`：允许覆盖默认能力动词。

Journey DTO 原样投影这些受控内容字段。前端再经过 `LearnerMissionViewModel` 聚合、回退和排序：旧 revision 缺少新字段时使用标题、描述和活动类型默认指引，因此不会出现空白页面。

这些字段只允许纯文本和字符串列表；不允许 HTML、CSS、组件名、脚本或任意 URL，避免把配置中心变成不受治理的页面构建器。

## 共享展示模型

学员真实 Journey 与管理员候选 payload 分别适配为同一个 `LearnerMissionViewModel`：

```text
Journey DTO ───────────────┐
                           ├─ LearnerMissionViewModel ─ LearnerMissionCard
Candidate path payload ────┘
```

管理员预览复用 `LearnerMissionCard`，不再维护一套只显示节点数量的“伪预览”。预览明确标注为“新学员初始视角”，避免假装模拟已有学员进度。

## 管理编辑策略

- 基础内容：名称、完成后能做到、目标、价值、步骤、通过标准、预计用时。
- 高级规则：适用对象、前置依赖、完成策略、资源绑定。
- 数组字段采用可增删的短行编辑器，不要求管理员输入 JSON 或逗号协议。
- 大纲只展开当前分支；移动、复制、删除在行聚焦/悬停时出现并保留键盘访问。
- 保存草稿自动使用稳定审计说明“保存训练路径草稿”；发布说明仍由管理员填写。
- 所有资源继续在当前抽屉选择或快速创建并自动绑定，遵守上下文内完成原则。

## 默认内容表达

- 阶段 1：能用 3 分钟讲清公司与方案。
- 阶段 2：能独立讲解核心产品与适用场景。
- 阶段 3：能完成客户场景演示并通过考核。
- PPT 讲解录音任务默认说明准备、阅读、录制、检查并提交的步骤，以及时长、覆盖要点和评分阈值等通过标准。

默认内容只作为新环境 seed 和旧数据回退示例；生产培训人员可以在管理端全部修改。

## 兼容性与风险

- 不新增表、不修改活动类型、不改变发布和 enrollment 固定修订语义。
- 老 revision 通过可选字段默认值继续解析。
- 已报名学员继续固定旧 revision；只有管理员发布新 revision 后，新报名学员读取新内容。
- UI 改版可通过回滚前端部署恢复；合同字段是向后兼容添加，旧前端会忽略。
- 风险等级 P1：涉及核心学员页面和路径 JSON 合同，但无数据库迁移、无权限边界变化。

## 测试策略

- 后端：Pydantic 兼容解析、新字段完整投影、旧 payload 回退。
- 前端 ViewModel：旧/新 payload、锁定/完成/进行中、活动类型默认文案。
- 学员组件：首页只突出一个任务；目标、步骤、通过标准和主按钮可见；移动端无横向溢出。
- 管理组件：双栏布局、字段 round-trip、操作降噪、保存无需理由、候选真实预览。
- 浏览器：桌面与移动学员路径；桌面管理员编辑、预览、保存、检查、发布说明。

## 非目标

- 不新增第七种活动类型。
- 不重做全站首页、登录、导航和通用设计系统。
- 不实现任意拖拽页面搭建、富文本 CSS 或脚本扩展。
- 不改变实时对练和异步录音评分的执行边界。
