# ADR：新人训练采用任务优先展示与按需真实预览

> **Superseded / Legacy（2026-07-16）：** 本 ADR 仅保留当前在途界面的历史决策，不再授权 Phase/Module 或 v1 Journey 合同。目标页面与领域权威见 [`../newcomer-foundation-contract-index.md`](../newcomer-foundation-contract-index.md)。

- 日期：2026-07-12
- 状态：Superseded（保留为 Legacy 历史记录）
- 关联：`2026-07-12-newcomer-training-activity-orchestration.md`

## 决策

新人训练领域继续使用 `TrainingPath → Phase → Module → Activity` 作为配置和治理结构，但学员界面不直接复刻这棵结构。学员首页以当前可执行活动组成“任务驾驶舱”，阶段和模块仅作为位置与后续路径。

路径配置向既有 `v1` JSON 合同增加受控、可选的学员表达字段；Journey 服务负责投影，前端统一适配为 `LearnerMissionViewModel`。旧 revision 使用活动类型默认文案回退。

管理端由常驻三栏改为“大纲 + 单对象编辑”两栏。预览按需打开，并复用学员端任务组件。此决策取代关联 ADR 中“右侧常驻预览校验”的布局决定，不改变其活动编排、权限、修订和资源治理决定。

## 原因

- 领域模型适合保证数据完整性，不等于最适合直接呈现给学员。
- 当前阶段名无法回答“现在具体做什么”，导致首屏抽象且行动成本高。
- 常驻三栏在常见桌面宽度下压缩大纲和表单，预览又不是真实渲染，空间成本高于价值。
- 受控内容字段让培训人员无需改代码即可改善体验，同时避免任意页面搭建器带来的兼容和安全负担。

## 后果

- 学员端和管理预览必须共享展示组件与 ViewModel 合同。
- 新字段必须向后兼容；不得为了展示内容升级数据库或破坏旧 revision。
- 新增全新执行能力仍需代码；新增阶段、模块、产品、材料、题目和学员文案不需要代码。
- 管理员预览仅承诺候选路径的“新学员初始视角”，不伪造已有学员的状态和成绩。

## 被拒绝方案

- 保持三栏、只缩小字号：不能解决信息任务冲突和伪预览问题。
- 直接把阶段改名得更具体：只能改善种子内容，无法保证每个活动都有目标、步骤与通过标准。
- 引入低代码页面构建器：原型阶段成本、治理和迁移负担远高于当前需求。
- 创建 `schema_version = v2`：新字段全为可选添加，版本分叉只会制造双轨。
