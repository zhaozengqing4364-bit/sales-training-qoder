# 企业新人训练路径平台 V0.9 全量可用闭环

> **状态：Superseded / Legacy 产品历史（2026-07-16）。** 本文保留 V0.9 讨论和当前能力盘点，不再作为目标实现或验收依据；Foundation target 见 [`../newcomer-foundation-contract-index.md`](../newcomer-foundation-contract-index.md)。文内训练任务模板、旧路由与 Realtime 阶段只作为迁移输入。

> 历史状态：2026-07-06 的产品/技术方案稿，仅用于理解迁移背景，不再作为实现与验收依据
> 更新时间：2026-07-06
> 相关术语：`CONTEXT.md` 中的“新人训练路径”“训练任务模板”“训练达标档案”“AI 补练教练”“金字塔演讲训练”

## 1. 结论

当前系统已经具备“企业新人训练路径平台”的大量底座能力：新人训练路径、PPT/录音评分、商务礼仪文章小单元、题库/考卷、AI Coach、训练记录、快照、权限、审计和配置发布治理。

但它还不是一个可以直接作为商业 V1 长期交付的版本。当前更准确的状态是：

| 可用层级 | 判断 |
|---|---|
| 内部演示 | 接近可用。已有本地 deterministic 闭环和质量门禁记录。 |
| 受控试点 | 还差产品出口收敛。需要训练达标档案、培训负责人工作台和任务模板配置口径。 |
| 商业 V1 | 还差运营闭环。需要复核/重练工作流、真实 provider 验证、上线配置包和可回滚发布路径。 |

V0.9 的目标不是继续扩大实时对练或把后台做成流程编排器，而是先把已有能力组织成一个可试点的全量闭环：

```text
后台发布训练路径
→ 新人完成学习、答题、录音/演讲提交
→ AI 初评并沉淀能力项证据
→ 未达标进入 AI 补练或重练
→ 培训负责人复核
→ 形成训练达标档案
→ 基于档案决定进入下一阶段、继续重练或人工跟进
```

这里的“全量闭环”不是一次性做完所有高级能力，而是第一版必须把每一条关键业务链路都闭上：

| 链路 | V0.9 必须闭合到哪里 |
|---|---|
| 配置链路 | 从后台配置、校验、发布到前台读取；配置缺失时 fail-closed 并提示管理员修复。 |
| 学习链路 | 从任务领取、材料学习、答题或录音提交到结果查看；新人不需要离开当前任务流程补资料。 |
| 评分链路 | 从规则判分或 AI 初评到能力项证据；评分标准、Prompt、通过线有快照。 |
| 补练链路 | 从未达标能力项到 AI 补练或重练任务；再次提交后更新档案。 |
| 复核链路 | 从待复核列表到培训负责人确认达标、要求重练、标记人工跟进；动作留审计。 |
| 准入链路 | 从训练达标档案到真实语音对练是否开放；训练未达标或 provider 未就绪都不开放。 |
| 复盘链路 | 从单人档案到团队配置优化；先保留证据和口径，不在 V0.9 做复杂数据大屏。 |

## 2. V0.9 产品定位

产品对外定位：

> 企业新人训练路径平台。

北极星结果：

> 每个新人都有一份可信的训练达标档案。

第一版主用户：

> 培训负责人。新人端先保证任务完成顺畅，培训负责人端要能判断谁达标、谁没达标、为什么、下一步怎么推进。

V0.9 不以“实时语音对练可用”为完成标准。真实语音对练是后续训练阶段，必须按训练准入开放，不阻塞 V0.9 的可用闭环。

## 3. V0.9 闭环范围

V0.9 先交付以下闭环：

1. 管理员配置并发布训练路径。
2. 新人学习标准材料、PPT 或文档。
3. 新人完成商务礼仪小单元答题或最终考试。
4. 系统用规则或 AI 对答案和提交物初评。
5. 未达标时强推荐 AI 补练教练。
6. 新人完成金字塔演讲训练，提交演讲录音或内容。
7. 系统生成训练达标档案。
8. 培训负责人复核档案，执行确认达标、要求重练或标记需人工跟进。
9. 系统按档案结论更新下一阶段准入状态。
10. 配置或评分异常进入配置异常队列，不伪装成学员未完成。

真实语音对练在 V0.9 中只作为后续阶段：

```text
已完成前置训练后开放。
当前需先完成金字塔演讲并通过复核。
```

### 3.1 端到端闭环地图

```text
管理员配置训练路径
  → 发布默认训练包
  → 学员领取任务
  → 学习材料 / PPT / 文档
  → 答题 / 上传录音 / 提交演讲内容
  → 规则判分或 AI 初评
  → 写入能力项证据
  → 生成或更新训练达标档案
  → 未达标进入 AI 补练或重练
  → 再次提交并更新档案
  → 培训负责人复核
  → 确认达标 / 要求重练 / 标记人工跟进
  → 达标后开放下一阶段，真实语音对练仍需 provider readiness
```

### 3.2 角色主任务

| 角色 | V0.9 主任务 | 不应让他承担的任务 |
|---|---|---|
| 管理员 | 配置训练任务、材料、题目、评分标准、补练策略和发布状态 | 编排上传、转写、评分、写库等底层技术步骤 |
| 新人 | 按任务完成学习、答题、录音、演讲和补练 | 自己判断训练路径、寻找缺失材料、理解 Prompt 或技术错误 |
| 培训负责人 | 查看档案、复核证据、决定达标/重练/人工跟进 | 从散落记录中拼结论、手工追踪每个能力项 |
| AI 补练教练 | 解释弱项、生成训练卡、批改答案、推荐回看章节 | 替代培训负责人做最终达标裁决 |
| 系统 | 保证配置治理、状态流转、证据快照、权限和审计 | 用前端隐藏按钮替代后端校验 |

### 3.3 最小页面出口

V0.9 不需要先做很多页面，但必须有清晰出口：

| 出口 | 目标用户 | 主操作 | 成功标准 |
|---|---|---|---|
| 训练路径配置页 | 管理员 | 发布训练路径 | 至少一条默认训练路径可发布、回滚、诊断配置异常 |
| 新人训练首页 | 新人 | 继续当前任务 | 新人 3 秒内知道当前该练什么、为什么被锁定、下一步是什么 |
| 任务详情页 | 新人 | 学习、答题或提交录音 | 缺材料、评分中、评分失败、未达标都有明确反馈和恢复动作 |
| 训练达标档案页 | 培训负责人 | 查看证据并判断是否达标 | 能回答练过什么、证据是什么、AI 怎么评、谁复核、是否重练 |
| 达标验收工作台 | 培训负责人 | 处理待复核新人 | 待复核、未达标、需重练、配置异常分组清楚 |

## 4. 后台配置原则

V0.9 必须遵循：

> 固定任务类型，动态任务实例。

也就是说，系统可以内置稳定任务类型和兼容 key，但训练内容、材料、题目、评分标准和启停状态必须来自后台配置和发布治理。

### 4.1 固定任务类型

V0.9 先支持 5 类稳定任务类型：

| 任务类型 | 用途 | 示例任务实例 |
|---|---|---|
| `material_learning` | 标准材料、PPT、文档学习 | 新人销售话术材料学习 |
| `article_quiz` | 文章学习 + 小测 / 考试 | 商务礼仪学习与测验 |
| `audio_scoring` | 录音上传 + 转写 + AI 评分 | PPT 讲解录音、金字塔演讲 |
| `ai_remediation` | AI 补练教练 | 商务礼仪未达标补练 |
| `realtime_roleplay_gate` | 真实语音对练准入 / 占位 | 真实客户场景对练入口 |

### 4.2 动态任务实例

管理员配置的是训练任务实例，而不是底层技术步骤。

每个训练任务模板至少应声明：

| 配置项 | 说明 |
|---|---|
| 任务顺序 | 第几关，是否阻塞下一关 |
| 任务名称与说明 | 学员看到的任务标题、说明、操作引导 |
| 材料要求 | 绑定标准 PPT、文档、附件或学习文章 |
| 提交物 | 答题、录音、演讲内容、AI 训练卡或对练结果 |
| 评分标准 | 评分 Prompt、rubric、输出结构、通过线 |
| 能力项 | 本任务影响哪些能力项 |
| AI 补练策略 | 是否启用、是否必做、触发条件 |
| 复核策略 | 是否需要培训负责人确认 |
| 失败策略 | 缺材料、缺 Prompt、转写失败、AI 评分失败时如何展示 |

系统内部可以执行上传、转写、评分、记录、复核、重练，但这些底层步骤不直接暴露给管理员自由编排。

### 4.3 配置发布闭环

配置发布不是“保存成功”就结束。V0.9 至少要闭合下面四步：

| 步骤 | 要求 |
|---|---|
| 保存草稿 | 允许管理员补齐训练任务实例；缺材料、缺题目、缺 Prompt 时标记为草稿不可发布。 |
| 发布前校验 | 校验任务顺序、材料绑定、题目数量、评分 Prompt、通过线、能力项映射和准入条件。 |
| 发布生效 | 只影响未来新任务、新提交、新评分；历史记录继续读取创建时快照。 |
| 回滚或停用 | 回滚只影响未来，不重写历史成绩；停用后前台入口锁定并显示管理员可操作原因。 |

配置异常必须进入“配置异常”分组，而不是在新人端表现为“暂无任务”或在培训负责人端表现为“学员未完成”。

### 4.4 允许内置的内容

以下内容可以稳定写在代码里：

- 任务类型枚举。
- 兼容 module key。
- 默认兜底文案。
- 安全失败策略。
- 权限和审计底线。
- 数据快照和版本治理规则。

以下内容不得写死在页面或服务逻辑里：

- 具体 PPT 材料。
- 学习文章正文。
- 商务礼仪小单元组成。
- 题目和答案。
- 评分 Prompt。
- 通过线。
- 金字塔演讲评分标准。
- AI 补练是否启用。
- 真实语音对练准入条件。

### 4.5 不引入问题的配置护栏

| 风险 | 护栏 |
|---|---|
| 页面继续写死商务礼仪、PPT、金字塔演讲等内容 | 前端优先读取发布配置；fallback 只用于兜底和兼容，不作为业务事实来源。 |
| 后台变成通用流程编排器 | 管理员只配置任务实例和策略，底层步骤由代码按固定任务类型执行。 |
| 配置变更污染历史成绩 | attempt、submission、score result、AI Coach session 和档案证据必须保留快照或 revision 引用。 |
| 配置缺失导致新人卡住且不知道原因 | 学员端显示“当前任务配置待完善”，培训负责人和管理员端显示具体缺失项。 |
| 发布后立刻改变所有人状态 | 发布默认只影响未来；历史重评必须是独立高风险动作，V0.9 不作为默认能力。 |

## 5. 训练达标档案

训练达标档案是 V0.9 的产品出口。

它不是训练记录列表，也不是考试分数详情页。它要回答：

- 他练过什么？
- 提交了什么证据？
- AI 按什么标准评？
- 哪些能力达标，哪些没达标？
- 是否有人复核过？
- 没达标后有没有重练？
- 当前能不能进入下一阶段？

### 5.1 档案结构

第一版档案建议包含：

| 区块 | 内容 |
|---|---|
| 新人概览 | 姓名、部门、训练路径、当前阶段、总体状态 |
| 任务进度 | 已完成、待提交、待评分、待复核、需重练 |
| 能力项状态 | 7 个通用能力项的 AI 初评、人工确认和重练状态 |
| 证据链 | 每个任务的材料快照、提交物、转写、答案、评分标准、AI 反馈 |
| AI 补练记录 | 训练卡、得分、薄弱点、建议回看章节、达标进度 |
| 复核记录 | 培训负责人动作、原因、时间、结论 |
| 下一步 | 确认达标、要求重练、标记需人工跟进 |

### 5.2 能力项

V0.9 先使用一套内置的通用新人销售能力模型：

1. 表达清晰度
2. 结构化讲解
3. 产品理解
4. 客户视角
5. 需求识别
6. 异议回应
7. 商务礼仪与职业表达

训练任务产生证据，评分标准映射能力项，档案汇总能力项状态。

AI 可以给出分数、证据、反馈和建议，但不能临时发明新的能力项。

### 5.3 达标状态

档案里的状态要区分 AI 初评和人工确认：

| 状态 | 含义 |
|---|---|
| 未训练 | 还没有提交相关证据 |
| AI 初评达标 | AI 根据评分标准认为达标 |
| AI 初评未达标 | AI 根据评分标准认为未达标 |
| 需重练 | 已触发补练或重练任务 |
| 待人工复核 | AI 或系统无法给出最终判断，需要培训负责人处理 |
| 已确认达标 | 培训负责人确认达标 |
| 已确认未达标 | 培训负责人确认未达标 |

### 5.4 证据链最小字段

训练达标档案的可信性来自证据，而不是来自“完成率”。每条证据至少要能追溯：

| 字段 | 说明 |
|---|---|
| `task_id` / `task_revision` | 哪个训练任务、哪个发布版本产生的证据 |
| `evidence_type` | 答题、录音、转写、AI 评分、AI 补练、人工复核、重练结果 |
| `submitted_by` / `reviewed_by` | 谁提交、谁复核 |
| `submitted_at` / `reviewed_at` | 关键时间 |
| `material_snapshot` | 学员当时看到的材料或材料版本 |
| `scoring_snapshot` | AI 或规则当时采用的评分标准、Prompt、通过线 |
| `result` | 分数、达标状态、弱项、建议 |
| `audit_trace` | 审计事件或 trace，用于排查但普通用户默认不展示 |

### 5.5 档案状态机

V0.9 可以先用一套轻量状态，但必须集中定义，不能散落在页面判断里：

| 档案状态 | 进入条件 | 下一步动作 |
|---|---|---|
| `not_started` | 新人尚未开始任何关键任务 | 引导开始第一项训练 |
| `in_training` | 有任务进行中或等待提交 | 继续当前任务 |
| `ai_evaluating` | 有提交物正在转写或评分 | 等待结果，失败后可重试或转人工 |
| `needs_remediation` | 有关键能力项 AI 初评未达标 | 进入 AI 补练或生成重练任务 |
| `pending_review` | 关键证据已齐，等待培训负责人复核 | 培训负责人确认达标、要求重练或人工跟进 |
| `approved` | 培训负责人确认达标 | 开放下一阶段或标记可上岗 |
| `rejected` | 培训负责人确认未达标 | 要求重练或人工跟进 |
| `blocked_by_config` | 配置缺失或停用导致档案不可信 | 管理员修复配置后重新进入可训练状态 |

### 5.6 能力项汇总规则

能力项状态不能只取最后一次总分。建议规则：

1. 先汇总所有映射到该能力项的训练证据。
2. 优先使用最新一次有效提交，但保留历史弱项和重练记录。
3. AI 只给初评和证据，不生成最终人工结论。
4. 培训负责人复核可以覆盖最终达标状态，但不能删除原始 AI 证据。
5. 配置异常、评分失败、证据缺失时，该能力项状态为“待确认”或“配置异常”，不得显示为达标。

## 6. 培训负责人达标验收工作台

V0.9 后台首页不应是数据大屏，也不应是训练记录数据库。

它应该是：

> 达标验收工作台。

### 6.1 分组

工作台按培训负责人要处理的任务分组：

| 分组 | 含义 |
|---|---|
| 待复核 | 新人已完成训练并有 AI 初评，但还没有人工确认 |
| 未达标 | AI 初评或人工复核显示未达标 |
| 需重练 | 已生成重练任务但新人还未重新提交 |
| 已达标 | 关键能力项已确认达标 |
| 配置异常 | 材料、题目、评分标准、Prompt 或路径配置缺失，导致档案不可信 |

### 6.2 单个新人卡片

每张卡片只回答三个问题：

1. 当前能不能判定达标？
2. 卡在哪个能力项或任务？
3. 培训负责人下一步要做什么？

### 6.3 第一版动作

V0.9 只保留三个主动作：

| 动作 | 含义 |
|---|---|
| 确认达标 | 培训负责人认可当前证据，可进入下一阶段或上岗 |
| 要求重练 | 针对未达标能力项生成重练任务 |
| 标记需人工跟进 | AI 评分或提交证据不足以判断，需要线下沟通或主管介入 |

暂不把“手动改分”“删除成绩”“复杂审批流”作为主动作。

### 6.4 复核动作闭环

每个复核动作都必须产生业务后果和审计记录：

| 动作 | 后果 | 审计 |
|---|---|---|
| 确认达标 | 更新档案状态和能力项人工确认状态；满足条件时开放下一阶段 | 记录复核人、原因、关联证据、时间 |
| 要求重练 | 生成或更新重练任务，绑定未达标能力项和来源证据 | 记录来源任务、弱项、重练要求、截止状态 |
| 标记需人工跟进 | 档案进入人工跟进状态，不开放下一阶段 | 记录原因、责任人、后续处理说明 |

复核不是“改分”。如果培训负责人认为 AI 评分不准确，应记录校准意见和人工判断，保留原始 AI 分数和理由。

### 6.5 重练闭环

重练必须可追踪前后变化：

```text
未达标能力项
→ 培训负责人要求重练或系统推荐补练
→ 生成重练任务
→ 新人重新提交
→ AI 或规则再次初评
→ 档案展示前后对比
→ 培训负责人复核是否达标
```

重练任务至少要绑定：

- 来源任务或来源证据。
- 未达标能力项。
- 重练目标。
- 重新提交物。
- 前后对比。
- 当前状态：待完成、进行中、已完成、已取消。

## 7. AI 补练教练

当前系统里的商务技巧 AI 教练已经更接近“AI 补练教练”，不是简单自由问答。

它的 V0.9 定位：

> 学习材料或小测之后的 AI 辅导与补练角色，围绕当前小单元生成训练卡、批改答案、解释薄弱点、推荐回看章节，并给出 AI 初评达标、可上场或待人工复盘的阶段判断。

边界：

- 默认不是必经环节。
- 未达标后强推荐进入。
- 关键岗位或关键能力项可以配置为必做。
- 不能替代培训负责人最终确认达标。
- 不能把自由聊天记录直接当作达标结论。

### 7.1 AI 补练教练在学习后的作用

学习完商务礼仪等内容后，AI 的作用不是“陪聊”，而是把学习结果转成可补强的训练动作：

| 场景 | AI 应做什么 | AI 不应做什么 |
|---|---|---|
| 学员刚学完文章 | 生成围绕当前章节的小题、情景判断或表达改写训练卡 | 直接宣布学员已达标 |
| 小测未达标 | 解释错因、指出薄弱能力项、推荐回看章节、安排补练 | 只给泛泛鼓励或让学员自由提问 |
| 简答题质量不足 | 按 rubric 指出缺少客户视角、结构或礼仪表达 | 只返回一个总分 |
| 补练多轮后仍不稳 | 标记待人工复盘，给培训负责人可读摘要 | 无限继续聊天，掩盖未达标事实 |

### 7.2 AI 输出治理

V0.9 的 AI 输出必须具备：

- 依据：引用训练任务、题目、答案、转写或评分标准。
- 不确定性：标记缺证据、无法判断或需要人工复核的原因。
- 可追踪：记录 Prompt 版本、评分标准快照、模型或 provider 标识、耗时和错误码。
- 可降级：AI 失败时新人仍能提交，培训负责人看到“待人工复核”而不是空白。
- 可编辑/可复核：培训负责人可以确认、驳回或要求重练，但不删除原始 AI 证据。

AI 不直接执行以下动作：

- 确认最终达标。
- 删除或覆盖历史证据。
- 自动开放真实语音对练。
- 自动外发消息或批量改状态。

### 7.3 真实语音对练准入

真实语音对练必须同时满足两个条件：

| 条件 | 说明 |
|---|---|
| 训练准入 | 前置任务达标，关键能力项没有阻塞项，培训负责人已确认或规则允许进入下一阶段。 |
| 技术准入 | realtime provider readiness 通过，音频格式、鉴权、连接和降级策略可用。 |

任一条件不满足，入口都应该锁定并说明原因：

- 训练未达标：展示需要补练的能力项和任务。
- 待人工复核：展示“等待培训负责人确认”。
- 配置异常：展示管理员需要修复的配置项。
- provider 未就绪：展示“真实语音对练暂未开放”，不影响前置训练档案。

## 8. 当前已有能力 / 缺口 / 优先级

| 闭环环节 | 当前状态 | 主要缺口 | 优先级 |
|---|---|---|---|
| 管理员配置训练路径 | 已有 path config、材料、文章、考卷、AI Coach 配置和发布治理 | 需要收敛成默认可试点训练包，减少配置分散感 | P1 |
| 新人学习材料 | 已有商务礼仪文章、小单元、章节完成、学习后考试 gate | 页面文案要从模块功能转为训练任务 | P2 |
| 答题与 AI 初评 | 已有小单元测验、最终考试、规则判分、简答 AI 评分、逐题解析 | 评分结果需统一回流到 7 个通用能力项 | P1 |
| AI 补练教练 | 已有训练局、训练卡、批改、薄弱点、建议章节、达标进度 | 要产品化为未达标补弱动作，而不是普通聊天入口 | P1 |
| 金字塔演讲训练 | 目前更像路线概念，未完全沉淀为一等关卡 | 需要任务模板、提交物、评分标准、能力项映射 | P0 |
| 培训负责人复核 | 有训练记录、管理端看板、风险学员、记录详情 | 缺确认达标、要求重练、人工跟进的一等工作流 | P0 |
| 训练达标档案 | 有记录、快照、评分、AI Coach progress、历史回放 | 缺面向单个新人的档案页和证据链聚合 | P0 |
| 重练闭环 | 已有部分重练、补练、AI Coach 机制 | 需要把未达标能力项、重练任务、再提交和档案更新串起来 | P0 |
| 真实语音对练 | local provider 与治理基础较多，真实 StepFun 仍有音频格式或提交策略问题 | V0.9 先锁定为后续阶段，不阻塞可用闭环 | P2 |

### 8.1 现状判断口径

当前系统的优势是底座已经比较多，不是从零开始：

- 配置侧已有 path config、材料、文章、考卷、Prompt、AI Coach 配置和发布治理。
- 学员侧已有材料学习、章节完成、考试、录音上传、转写和评分结果展示。
- AI 侧已有商务技巧训练局、训练卡、薄弱点、建议章节和达标进度。
- 主管/培训负责人侧已有 supervisor review、readiness status、retraining task 等能力雏形。
- 数据侧已有快照、revision、操作记录、评分 Prompt、provider 错误码等基础。

但 V0.9 不能仅靠“这些模块都存在”就算可用。必须补上产品聚合层：

- 单个新人训练达标档案。
- 培训负责人达标验收工作台。
- 能力项统一汇总。
- 复核动作和重练动作。
- 配置异常诊断和 fail-closed。

### 8.2 不引入问题的实现原则

后续实现必须按下面原则推进，避免为了闭环制造新的技术债：

| 原则 | 说明 |
|---|---|
| 先读模型，后写页面 | 页面只展示 ViewModel，不能直接平铺数据库对象、原始枚举或 Prompt。 |
| 先聚合只读，再加写动作 | 先做档案只读聚合，验证证据口径，再增加复核/重练写操作。 |
| 写操作以后端为准 | 确认达标、要求重练、开放下一阶段必须由后端校验权限、状态和对象归属。 |
| 配置缺失显性失败 | 配置缺失是配置异常，不是学员未完成，也不是系统“暂无数据”。 |
| AI 证据可追踪 | AI 输出必须保留评分标准和版本，不把自由文本当作已验证事实。 |
| 不扩大实时对练范围 | 真实语音对练只做准入衔接，不把 StepFun 修复作为 V0.9 主线 blocker。 |
| 不做通用流程引擎 | 固定任务类型足够支撑 V0.9；任务实例动态配置即可。 |

### 8.3 需要警惕的伪闭环

以下做法看似完成，实际会引入问题：

| 伪闭环 | 为什么有问题 |
|---|---|
| 用模块完成率代替达标档案 | 不能回答证据、评分标准、能力项、复核和重练问题。 |
| 在前端写一个“达标”按钮 | 绕过后端状态、权限、审计和重练关系。 |
| 只在 AI Coach 页面展示弱项 | 培训负责人无法在档案和工作台里推进复核。 |
| 把真实语音对练修通当作 V0.9 完成 | 会跳过前置训练证据和达标验收。 |
| 管理员能自由拖拽底层步骤 | 容易破坏上传、转写、评分、快照、审计的不变量。 |
| 配置异常时隐藏入口 | 会把配置问题误判为学员没有任务。 |

## 9. V0.9 不做事项

V0.9 明确不做：

- 不做完全动态任务类型系统。
- 不做通用流程编排器。
- 不把真实语音对练作为首个可用闭环 blocker。
- 不让 AI 补练教练替代培训负责人最终确认。
- 不把模块完成率或考试总分当作训练达标档案。
- 不在页面里写死具体材料、题目、评分 Prompt 或训练内容。
- 不引入复杂审批流、多人会签、成绩仲裁和绩效联动。
- 不做历史成绩自动重评。
- 不做跨租户或跨企业的能力模型自定义市场。
- 不把团队分析大屏作为第一版验收条件。

## 10. 后续实施顺序

推荐实施顺序：

### Step 1：训练达标档案只读聚合

先做管理员视角的只读档案页，聚合现有记录、快照、评分、AI Coach progress 和复核占位。

验收口径：

- 能看到新人练过什么。
- 能看到提交证据。
- 能看到 AI 评分标准和结果。
- 能看到能力项状态。
- 能看到是否需要重练或人工跟进。

### Step 2：达标验收工作台

把后台首页收敛为工作台，按待复核、未达标、需重练、已达标、配置异常分组。

验收口径：

- 培训负责人进入 3 秒内知道先处理谁。
- 每个新人卡片有明确下一步动作。
- 配置异常不伪装成暂无数据。

### Step 3：复核与重练动作

新增确认达标、要求重练、标记需人工跟进三个动作。

验收口径：

- 动作写审计。
- 动作更新档案状态。
- 要求重练能关联能力项和训练任务。
- 不允许前端绕过后端权限。

### Step 4：金字塔演讲训练模板

把金字塔演讲作为 `audio_scoring` 类型的后台可配置任务实例，而不是写死新页面流程。

验收口径：

- 管理员可配置任务名称、材料、评分 Prompt、能力项和通过线。
- 新人提交录音或演讲内容。
- AI 评分回流到表达清晰度、结构化讲解等能力项。

### Step 5：配置收敛与发布包

整理一个 V0.9 默认训练路径配置包。

验收口径：

- 标准材料/PPT、商务礼仪、小测、AI 补练、金字塔演讲和真实语音对练准入都从发布配置读取。
- 前端只使用后台标题、说明、按钮和启停状态，页面内 fallback 只作兜底。
- 配置缺失时 fail-closed，并给管理员可操作诊断。

### Step 6：真实语音对练准入接入

在前置训练证据和 provider readiness 都满足后，再开放真实语音对练。

验收口径：

- 没有前置证据时入口锁定。
- provider readiness 失败时入口锁定。
- 对练目标来自能力项弱项或训练档案，不是孤立 demo。

### Step 7：团队复盘口径

受控试点后再做团队层面的轻量复盘，不先做大屏。

验收口径：

- 能看到常见未达标能力项。
- 能看到哪些任务最容易触发重练。
- 能看到配置异常次数。
- 指标有统计范围、时间范围、数据来源和排除口径。

## 11. 判定标准

V0.9 可以进入受控试点的标准：

- 至少一条默认训练路径可发布。
- 新人能完成学习、答题、录音/演讲提交。
- AI 初评能沉淀到能力项。
- 培训负责人能看到训练达标档案。
- 培训负责人能确认达标、要求重练或标记人工跟进。
- 配置缺失、评分失败、转写失败、权限不足都有明确反馈。
- 真实语音对练即使未开放，也不会破坏前置训练闭环。

### 11.1 受控试点验收清单

| 维度 | 验收标准 | 证据 |
|---|---|---|
| 默认路径 | 至少一条训练路径从草稿校验到发布可用 | 后台发布记录、前台读取发布配置 |
| 学员路径 | 新人能按顺序完成学习、答题、录音或演讲提交 | 一条真实或 deterministic 训练记录 |
| AI 初评 | AI 或规则评分能写入能力项证据 | 评分结果、能力项映射、评分快照 |
| 补练 | 未达标后能进入 AI 补练或生成重练任务 | 补练记录、重练任务、前后对比 |
| 档案 | 培训负责人能打开单人训练达标档案 | 档案页或聚合 API 结果 |
| 复核 | 培训负责人能确认达标、要求重练、标记人工跟进 | 审计记录、档案状态变化 |
| 配置异常 | 缺材料、缺题目、缺 Prompt、缺通过线时不能伪装成功 | 配置异常分组和用户可理解错误 |
| 权限 | 新人不能看他人档案，普通用户不能执行复核动作 | 后端权限测试或手工验证记录 |
| 历史快照 | 发布新配置不改变历史提交的材料和评分依据 | 历史记录仍读取 snapshot 或 revision |
| 实时对练 | 未满足训练准入或 provider readiness 时入口锁定 | 锁定原因和不影响前置闭环的验证 |

### 11.2 失败状态验收

V0.9 不能只验证 happy path，还要验证以下失败态：

| 失败态 | 用户看到什么 | 系统怎么处理 |
|---|---|---|
| 材料缺失 | 当前任务配置待完善 | 管理员看到缺失材料，学员不能提交无效任务 |
| 题目缺失 | 当前测验暂不可用 | 进入配置异常，不计为学员未完成 |
| Prompt 缺失 | 当前评分标准待配置 | 不调用 AI，不生成伪评分 |
| 转写失败 | 转写失败，可按策略重试或提交人工复核 | 保留上传证据和错误码 |
| AI 评分失败 | 评分失败，等待人工复核或稍后重试 | 不显示达标，不覆盖历史有效评分 |
| 无权限 | 你没有权限查看或处理该档案 | 后端拒绝并记录必要审计 |
| provider 未就绪 | 真实语音对练暂未开放 | 不阻塞学习、答题、演讲、档案和复核 |

## 12. 发布、回滚与降级

V0.9 应按受控试点方式发布：

| 项 | 要求 |
|---|---|
| 开启 | 对指定企业、角色或训练路径开启；先用默认训练包。 |
| 关闭 | 可停用某条训练路径或某个任务实例；前台显示锁定原因。 |
| 回滚 | 回滚配置只影响未来新任务；历史记录继续读快照。 |
| 降级 | AI 失败时降级到人工复核；真实语音对练失败时不影响前置训练闭环。 |
| 观测 | 记录配置异常、提交失败、评分失败、重练次数、复核积压和准入锁定原因。 |

不建议 V0.9 一次性对所有新人开放。更稳妥的试点节奏：

1. 内部 deterministic 数据跑通完整闭环。
2. 单企业、少量新人试点。
3. 培训负责人使用达标验收工作台复核真实档案。
4. 根据重练与配置异常数据调整默认训练包。
5. 再决定是否接入真实语音对练。

## 13. 最终产品判断

当下面这句话成立时，V0.9 才算真正可用：

> 培训负责人不需要问开发、不需要翻日志、不需要拼 Excel，就能打开一个新人档案，判断他练过什么、证据是否可信、哪些能力达标、哪些没达标、谁复核过、要不要重练，以及能不能进入下一阶段。

如果只能证明“页面能打开”“录音能评分”“AI 能回复”，还不能算完成 V0.9。

如果能证明“配置、学习、提交、评分、补练、重练、复核、档案、准入、异常、审计”都形成闭环，即使真实语音对练暂未开放，也可以进入受控试点。
